01 · Test plan, objectives & scope

The plan below is transcribed from the Test Plan sheet of TestPlan_and_TestCases.xlsx. It governs the manual round run against the release APK 1.0.0+3.

1. Reference documents

KeyItemDetail
Figma designFood Delivery Mobile App UI Kit (Figma Community, file 1352761962360670057)
Meal data sourceTheMealDB Free API - https://www.themealdb.com/api.php
QA defect trackerJira - https://m25242305m.atlassian.net/
Automation suiteautomation/ (Appium + Java, TestNG)

2. Objectives

KeyItemDetail
O1Verify that every functional requirement in the brief behaves as specified on a real device.
O2Verify the non-functional requirements: Clean Architecture boundaries, no hard-coded strings, responsive layout and universal error handling.
O3Verify that the Arabic localization is complete and switches at runtime.
O4Confirm the release APK distributed through Firebase App Distribution behaves identically to the local debug build.
O5Raise a Jira defect for every failure, with severity, priority and screenshot evidence.

3. Scope

KeyItemDetail
In scopeSplash/Onboarding, Login, Sign Up, Home feed, Meal details, Cart and checkout, Vendor map, Orders, Profile (biometric, device info, photo, favourites, history), theme toggle, EN/AR localization, offline behaviour.
Out of scopeiOS build, App Store release, push notifications, real payment gateway, live vendor inventory, analytics and A/B testing.
Test basisRelease APK 1.0.0 (arm64-v8a), built from flutter_app/.

4. Testing types

KeyItemDetail
FunctionalPositive, negative, boundary and GUI (layout, copy, iconography) per screen.
NegativeInvalid input, wrong credentials, duplicate account, offline, missing API key.
LocalizationFull EN <-> AR switch on every screen, including plural forms.
CompatibilityCompact phone (360dp) and tablet (800dp); Android 13 and Android 14.
RegressionEvery fix from this cycle re-tested (see the Defect Log sheet).
ExploratoryOne pass with airplane mode across all screens to hunt unhandled exceptions.
