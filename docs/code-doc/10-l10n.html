StreetBite code documentation · §10 Localisation

StreetBite code documentation · Part I · Section 10 of 18 · Full indexتوثيق كود StreetBite · الجزء الأول · القسم 10 من 18 · الفهرس الكامل

10 · Localisation10 · التعريب

StreetBite ships two languages, English and Arabic, and the rule that makes it work is a ban: no widget may contain a literal sentence. Text is reached through AppLocalizations, and the domain and data layers hand up keys instead of strings. Arabic is not a translation layer bolted on at the end — the app cannot be used without it, because every message it can show exists in both files or it does not exist at all.

Two ARB files, app_en.arb as the template and app_ar.arb, each carrying 178 keys. The generated classes (app_localizations.dart 1,202 lines, the two locale subclasses 586 and 596) are excluded from the 158 hand-written file count.

يصدّر StreetBite لغتين، الإنجليزية والعربية، والقاعدة التي تجعل ذلك تعمل هي منع: لا يجوز أن يحمل أي ودجة جملة حرفية. ويوصل إلى النص عبر AppLocalizations، وتُرفع طبقتا المجال والبيانات مفاتيح بدل النصوص. والعربية ليست طبقة ترجمة أُلحقت في النهاية — فلا يُستخدم التطبيق بدونها، لأن كل رسالة يمكن أن تظهر موجودة في الملفين معًا أو غير موجودة أصلًا.

ملفا ARB: app_en.arb نموذجًا وapp_ar.arb، وفي كل منهما 178 مفتاحًا. والأصناف المولَّدة (app_localizations.dart بـ1,202 سطرًا، والصنفين المشتقَّين 586 و596 سطرًا) خارج عدّ الملفات الـ158 المكتوبة يدويًا.

The generator is configured to stay inside lib/المولِّد مضبوط ليبقى داخل lib/

l10n.yaml points arb-dir at lib/l10n and sets output-dir: lib/l10n/generated — deliberately not the build folder, so the compiled artefacts are visible and reviewable inside the source tree. Two flags matter: nullable-getter: false makes every call site read AppLocalizations.of(context) without a !, because the lookup is guaranteed non-null; and use-escaping: true lets a translation keep a literal brace without it being read as a placeholder, which the money strings need.

يوجّه l10n.yaml مجلد arb-dir إلى lib/l10n، ويضبط output-dir: lib/l10n/generated — لا مجلد البناء، عن قصد — حتى تكون المخرجات مرئية داخل شجرة المصدر وقابلة للمراجعة. وعلمان له أثر: nullable-getter: false يجعل كل موضع يقرأ AppLocalizations.of(context) من غير ! لأن البحث مضمون غير خالٍ؛ وuse-escaping: true يسمح لترجمة أن تحتفظ بمعلاق حرفي من غير أن يُقرأ وسيطًا، وهو ما تحتاجه نصوص المال.

An honest correction to a doc comment · تصحيح صريح لتعليق في الكود

The comment above trKey says the switch is exhaustive, so wiring a new ARB key is "a compile-time error rather than a runtime surprise". It is not: line 109 ends with _ => l10n.somethingWentWrong, so an unwired key compiles and falls back at runtime. The comment above trArgs tells the truth and records the scar — a key missing there once made the checkout button read "Something went wrong" instead of "Place order · $23.14". The documented rule that follows is the right one: any widget that renders text through a dynamic key must be covered by a test that asserts on the visible sentence.

يقول التعليق فوق trKey إن التبديل مستوفٍ، فربط مفتاح ARB جديد خطأه «خطأ ترجمة لا مفاجأة تشغيل». وهذا غير صحيح: السطر 109 ينتهي بـ_ => l10n.somethingWentWrong، فأي مفتاح غير مربوط يُصرَّف ويسقط إلى النص الاحتياطي وقت التشغيل. أما التعليق فوق trArgs فيقول الحق ويسجّل الأثر: مفتاحًا ناقصًا هناك جعل زر إتمام الطلب يقرأ «حدث خطأ ما» بدل «اطلب · $23.14». والقاعدة المكتوبة بعده هي الصحيحة: كل ودجة تعرض نصًا عبر مفتاح ديناميكي يجب أن يغطيها اختبار يجزم بالجملة المرئية.

Switching language at runtimeتغيير اللغة أثناء التشغيل

LocaleCubit (45 lines) owns one Locale, defaults to en, and persists the language code under streetbite_locale. Its state is fed into MaterialApp.locale inside app.dart, with supportedLocales: AppLocalizations.supportedLocales and the three generated delegates — so changing language re-resolves every string without a restart, and Flutter derives the RTL Directionality from the same value. There is no manual mirroring anywhere.

setLocale ignores a locale that is not in supportedLocales, and toggle() is what the EN/AR button in every app bar and on the splash screen calls. load() is called once from main(), before the first frame, so the app never opens in English for a split second on an Arabic device.

يمتلك LocaleCubit (45 سطرًا) Locale واحدة، ويفترض en، ويحفظ رمز اللغة تحت streetbite_locale. وتُغذّى حالته في MaterialApp.locale داخل app.dart مع supportedLocales: AppLocalizations.supportedLocales والمفوّضين الثلاثة المولَّدين — فتغيير اللغة يعيد حلّ كل نص دون إعادة إقلاع، ويستنتج Flutter Directionality الأيمن-اليساري من القيمة نفسها. ولا توجد مراآة يدوية في أي موضع.

ويتغاضى setLocale عن لغة ليست في supportedLocales، ويستدعي toggle() زرّ EN/AR في كل شريط علوي وعلى شاشة البداية. ويُستدعى load() مرة واحدة من main() قبل الإطار الأول، فلا يفتح التطبيق بالإنجليزية لحظةً على جهاز عربي.

Keeping the 178 keys honestكيف تبقى المفاتيح الـ178 صادقة

Two Python helpers exist for exactly this: scripts/check_unused_arb.py reports ARB keys that no Dart file references, and scripts/prune_arb.py removes them from both files so the two locales cannot drift in size. The same scripts are what keep the count of 178 meaningful rather than accumulated — an app that bans literal strings tends to accumulate dead keys faster than it accumulates dead code.

توجد أداتا Python لهذا بالضبط: يُبلّغ scripts/check_unused_arb.py عن مفاتيح ARB لا يشير إليها أي ملف Dart، ويزيل scripts/prune_arb.py هذه المفاتيح من الملفين معًا فلا يتباعَد حجم اللغتين. وهذه السكربتات نفسها هي ما يبقي عدد 178 معنويًا لا متراكمًا — فتطبيق يمنع النصوص الحرفية يميل إلى تكديس المفاتيح الميتة أسرع من تكديسه الكود الميت.
