01 · What the app is

01 · ما هو هذا التطبيق

StreetBite is a hyperlocal food-discovery and ordering app. It shows the dishes you can order near you, lets you build a basket, check out with a payment strategy, and read the order back as a receipt. It ships as an Android APK and is written as a Clean Architecture capstone project, so every feature is traceable from a widget down to a use case.

User-visible features

  • Splash — brand mark, language switch, and a session restore that runs in parallel with a minimum display time.
  • Login / Sign Up — Firebase Authentication with declarative form validation and a circular fingerprint shortcut beside the primary button.
  • Biometric sign-in — a dedicated screen that auto-scans on a cold start when this device opted in; a failed scan drops you to the password form without signing you out.
  • Home feed — featured-meal PageView banner, category chips, a searchable GridView of meals, and a horizontal Hot Offers strip.
  • Meal details — instructions, favourite heart, and the add-to-cart stepper.
  • Browse tab — the category grid plus the entry point to the vendor map.
  • Cart — quantity steppers per line, a live money summary, payment choice, then checkout that writes the order to Cloud Firestore.
  • Order confirmation, then the Orders tab split into Current and Past, each row opening a full receipt.
  • Nearby Vendors — a Google Map with five seeded street-food markers.
  • Profile — behind a biometric gate: avatar upload, favourites strip, order history, device-information card, logout.
  • Settings — four appearances (light, dark, glass light, glass dark), language, and the biometric sign-in toggle.

Engineering goals the code is written against

  • Layered Clean Architecture with the dependency rule pointing inwards only.
  • SOLID demonstrated on purpose (PaymentMethod, FirestoreService, UseCase, repository interfaces).
  • No unhandled exception anywhere — failures are values, see §06.
  • Zero hard-coded UI text — every string is an ARB key, see §10.
  • Runs and is testable with no network, no Firebase project, and no Google Play Services.
  • Fully localised EN/AR with right-to-left layout, switchable at runtime.

تطبيق StreetBite هو تطبيق محلي لاكتشاف الطعام وطلبه. يعرض الأطباق التي يمكنك طلبها بالقرب منك، ثم يتيح لك بناء سلة الشراء وإتمام الدفع بأحد أساليب الدفع، وقراءة الطلب الذي أنشأته في شكل إيصال. يُصدَّر كملف APK لأندرويد، وقد كُتب كمشروع تخرّج بتطبيق المعمارية النظيفة (Clean Architecture)، وهذا يعني أن كل ميزة يمكن تتبّعها من الـ Widget نزولًا حتى Use Case.

الميزات الظاهرة للمستخدم

  • شاشة البداية (Splash) — العلامة التجارية ومبدّل اللغة واستعادة الجلسة في توازٍ مع حدٍّ أدنى لمدة العرض.
  • تسجيل الدخول / إنشاء حساب — عبر Firebase Authentication مع تحقّق declarative من الحقول وزرّ دائري للبصمة بجوار الزر الأساسي.
  • الدخول بالبصمة — شاشة مخصّصة تبدأ المسح تلقائيًا عند التشغيل البارد إذا كان هذا الجهاز قد اختار تفعيلها؛ وفشل المسح ينقلك إلى نموذج كلمة المرور دون تسجيل خروجك.
  • التغذية الرئيسية — شريط PageView للأطباق المميّزة، وشرائح التصنيفات، وGridView قابلة للبحث، وشريط أفقي للعروض الساخنة.
  • تفاصيل الطبق — طريقة التحضير، وقلب المفضّلة، ومُبدّل الكمية للإضافة إلى السلة.
  • تبويب تصفّح — شبكة التصنيفات مع نقطة الدخول إلى خريطة المطاعم.
  • السلة — مُبدّل كمية لكل سطر، وملخّص مبلغ حيّ، واختيار الدفع، ثم إتمام طلب يكتب السند في Cloud Firestore.
  • تأكيد الطلب، ثم تبويب الطلبات مقسوم إلى حالية وسابقة، وكل صف يفتح إيصالًا كاملًا.
  • مطاعم قريبة — خريطة Google Maps بخمس علامات مُ جهَّزة مسبقًا لأكشاك طعام شارع.
  • الملف الشخصي — خلف بوابة البصمة: رفع الصورة، وشريط المفضّلات، وسجل الطلبات، وبطاقة معلومات الجهاز، وتسجيل الخروج.
  • الإعدادات — أربع مظاهر (فاتح، داكن، زجاجي فاتح، زجاجي داكن)، واللغة، ومفتاح الدخول بالبصمة.

أهداف هندسية كُتب الكود على ضوئها

  • معمارية طبقية مع قاعدة التبعيات التي تشير إلى الداخل فقط.
  • تطبيق مقصود لمبادئ SOLID (PaymentMethod، وFirestoreService، وUseCase، وواجهات المستودعات).
  • لا وجود لأي استثناء غير معالَج — الأخطاء قيم وليس استثناءات، راجع §06.
  • صفر نصوص مكتوبة داخل الواجهة — كل نص هو مفتاح في ملفات ARB، راجع §10.
  • يعمل وقابل للاختبار بلا شبكة وبلا مشروع Firebase وبلا خدمة Google Play.
  • تعريب وت الترجمة بالكامل مع اتجاه من اليمين إلى اليسار وتبديل أثناء التشغيل.
Scope of this document · نطاق هذا المستند

Part I explains the design: why the layers are split the way they are, how a tap becomes a Firestore write, and what each subsystem guarantees. Part II is a mechanical reference — every one of the 158 Dart files, all 274 top-level declarations, and every shared constant and key — generated from the source tree on the day this document was written, so the counts are exact.

القسم الأول يشرح التصميم: لماذا انقسمت الطبقات بهذه الصورة، وكيف تتحوّلة ضغطة أصبع إلى كتابة في Firestore، وما الذي يضمنه كل نظام فرعي. القسم الثاني مرجع آلي — كل ملف من ملفات Dart الـ158، وجميع التعريفات العلوية الـ274، وكل ثابت ومفتاح مشترك — وقد وُلِّد من شجرة المصدر في يوم كتابة هذا المستند، لذا الأعداد دقيقة.
