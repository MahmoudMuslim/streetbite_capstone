StreetBite code documentation · §17 Constants, keys and identifiers

StreetBite code documentation · Part II · Section 17 of 18 · Full indexتوثيق كود StreetBite · الجزء الثاني · القسم 17 من 18 · الفهرس الكامل

17 · Constants, keys and identifiers17 · الثوابت والمفاتيح والمعرّفات

Part I explains what a value does. This section is where you look a value up: every literal the app keys itself on, in one table per family, each verified against the file that reads it. Six families cover the app — configuration constants, route names, on-device preference keys, the Firestore schema, message keys, and the widget identifiers the test layers address.

Everything here was re-read from source for this document, including the two places where the source contradicts its own comment. Those are called out rather than smoothed over.

يفسر الجزء الأول ما تفعله القيمة. وهذا القسم هو الموضع الذي تبحث فيه عن القيمة نفسها: كل حرفي يبني التطبيق عليه مفتاحًا، في جدول لكل عائلة، وكل سطر فيه مقروء من الملف الذي يقرأه فعلًا. وست عائلات تغطي التطبيق — ثوابت الإعداد، وأسماء المسارات، ومفاتيح التفضيلات على الجهاز، ومخطط Firestore، ومفاتيح الرسائل، ومعرّفات الودجات التي تخاطبها طبقتا الاختبار.

وأُعيد قراءة كل ما هنا من المصدر لأجل هذه الوثيقة، بما في ذلك الموضعان اللذان يُناقض فيهما الكود تعليقَه نفسه. وهذان مذكوران كما هما لا ملسعان.

17.1 · AppConstants — the one configuration file17.1 · AppConstants — ملف الإعداد الوحيد

Twenty-one static const members and nothing else: no methods, no state, a private constructor so nobody can instantiate it. The dartdoc's own reason for existing is that everything which "could otherwise be a magic value scattered through the code base lives here".

واحد وعشرون عضوًا static const ولا شيء غير ذلك: لا دوال ولا حالة، ومُنشئ خاص كي لا يستطيع أحد إنشاء مثيل منه. والسبب الذي يذكره توثيق الملف لنفسه أن كل ما "كان يمكن أن يبقى قيمة سحرية مبعثرة في الكود" يسكن هنا.

17.2 · Route names17.2 · أسماء المسارات

Twelve names, all of them strings the app compares against in exactly one place — the onGenerateRoute switch. Four tab indices sit beside them because the shell is addressed by index, not by name.

17.3 · What the phone keeps17.3 · ما يحفظه الهاتف

Seven SharedPreferences keys, all under the streetbite_ prefix. Three live as private fields of the data source that owns them, two as a public storageKey on their Cubit (so a widget test can assert on the same literal), and two in AppConstants. None is encrypted — shared_preferences is a plain XML file, which is exactly why §11 says the biometric opt-in is device-local convenience and not a security boundary.

سبعة مفاتيح SharedPreferences، كلها تحت بادئة streetbite_. ثلاثة تعيش كحقول خاصة في مصدر البيانات الذي يملكها، واثنان كـstorageKey عام على الدالة الحاكمة (فيستطيع اختبار ودجة أن يجزم بالحرفي نفسه)، واثنان في AppConstants. ولا واحد منها مشفَّر — فـshared_preferences ملف XML صريح، وهذا هو سبب قول §11 إن خيار البصمة راحة محلية على الجهاز لا حدّ أمان.

17.4 · The Firestore schema, as the code actually writes it17.4 · مخطط Firestore كما يكتبه الكود فعلًا

Pathالمسار Written byكاتبه Notesملاحظات
users/{uid}profile_repository_impl.dart One document per account: display name, email, photo URL, biometric flag. Writes always merge. مستند لكل حساب: الاسم المعروض والبريد ورابط الصورة وخيار البصمة. والكتابات تدمج دائمًا.
users/{uid}/favourites/{mealId}favourite_repository_impl.dart The document id is the meal id, so a heart is idempotent by construction — toggling twice cannot create two rows. معرّف المستند هو معرّف الطبق، فوضع القلب متكرر الأثر ببنائه — والنقر مرتين لا ينشئ سطرين.
orders/{uid}/items/{orderId}order_repository_impl.dart Unusual and worth reading twice: the user is the document under a top-level orders collection, and their orders are its items sub-collection. OrderModel.itemsSubCollection names the last segment. غير مألوف ويقرأ مرتين: المستخدم هو المستند تحت مجموعة orders العلوية، وطلباته مجموعتها الفرعية items. ويسمّي OrderModel.itemsSubCollection القطعة الأخيرة.
Schema residues · بقايا المخطط

FirestoreService declares three collection accessors — usersCollection(), ordersCollection(uid), favouritesCollection(uid) at firestore_service.dart:62-70 — under a comment that calls them "the only place collection paths are written down". Nothing calls them: the repositories assemble the same paths from AppConstants and pass finished strings to the generic helpers. The schema is centralised either way, but in the constants file, and the comment overstates what those three methods are for. AppConstants.favouritesCollection is the same story with zero readers.

The analyzer cannot see this: the class is used, so its public members look used too. Deleting the three accessors is safe and would make the comment true; it has not been done as part of writing this document because removing code is a change, not a correction of prose.

يُصرّح FirestoreService ثلاث أدوات للمجموعات — usersCollection() وordersCollection(uid) وfavouritesCollection(uid) في firestore_service.dart:62-70 — تحت تعليق يسمّيها «الموضع الوحيد الذي تُكتب فيه مسارات المجموعات». ولا يستدعيها أحد: فالمستودعات تبني المسارات نفسها من AppConstants وتمنح السلاسل الجاهزة لدوال الكتابة والقراءة العامة. فالمخطط مركزي على أي حال، لكن في ملف الثوابت، والتعليق يبالغ في ما لهذه الثلاث. وAppConstants.favouritesCollection قصته نفسها بصفر قارئ.

ولا يستطيع المُحلِّل أن يرى هذا: فالصنف مستعمل، فتبدو أعضاؤه العامة مستعملة معه. وحذف الأدوات الثلاث آمن ويجعل التعليق صادقًا؛ ولم يُفعَل أثناء كتابة هذه الوثيقة لأن حذف الكود تغيير لا تصحيح نص.

17.5 · Message keys17.5 · مفاتيح الرسائل

178 keys in each of app_en.arb and app_ar.arb, generated into lib/l10n/generated/ (§10). The rule the code follows is that nothing below the presentation layer returns a sentence: Failure carries a messageKey, Validators return one, and L10nX is the only place a key becomes text. A key that exists in one file and not the other is a compile-time error, which is why both files have exactly the same count.

178 مفتاحًا في كل من app_en.arb وapp_ar.arb، تُولَّد إلى lib/l10n/generated/ (§10). والقاعدة التي يمشي عليها الكود أن لا شيء تحت طبقة العرض يرجع جملة: فـFailure يحمل messageKey، وValidators ترجع واحدًا، وL10nX الموضع الوحيد الذي يتحول فيه المفتاح إلى نص. والمفتاح الموجود في ملف وغائب عن الآخر خطأ ترجمة، وهذا سبب تساوي عدد المفاتيح في الملفين.

The one documented gap · الفجوة المذكورة الوحيدة

L10nX.trKey maps failure keys to getters by hand, and the arm for biometricLockedOut is missing, so that failure falls through to the generic "something went wrong" sentence. §10 records it; it is a one-line fix and is deliberately not patched here.

يُرسم L10nX.trKey مفاتيح الفشل إلى دوال قراءة يدويًا، وفرع biometricLockedOut ناقص، فيسقط ذلك الفشل إلى الجملة العامة «حدث خطأ ما». ويسجّل §10 هذا؛ وهو إصلاح سطر واحد وتركه هنا مقصود.

17.6 · Identifiers the two test layers address17.6 · المعرّفات التي تخاطبها طبقتا الاختبار

Two mechanisms, two audiences, and they are usually declared together on the same widget (§12, §13).

ValueKey — 74 distinct literals. Dart only: invisible to the device, used by find.byKey in widget tests. Naming is thing_action_surface, e.g. details_open_cart_button, cart_emptied_snackbar, biometric_sign_in_switch.

SemanticId — 9 static identifiers plus 3 generated ones. Published to Android as the accessibility node's resource-id, which is what the Appium XPath addresses: login_button, go_to_sign_up_button, biometric_login_button, use_password_button, open_cart_button, hot_offers_list, open_map_button, save_favourite_button, reorder_button. The generated ones carry the meal id: add_to_cart_button_<mealId> and cart_line_quantity_<mealId>, with cart_line_quantity_text_<mealId> as the matching ValueKey — that last one is a Dart key only, so Appium cannot see it.

آليتان، وجمهوران، وغالبًا ما يُعلان معًا على الودجة نفسها (§12، §13).

ValueKey — أربعة وسبعون حرفيًا مميزًا. لدارت وحدها: خفي على الجهاز، ويستعمله find.byKey في اختبارات الودجة. وتسميته شيء_فعل_موضع مثل details_open_cart_button وcart_emptied_snackbar وbiometric_sign_in_switch.

SemanticId — تسعة معرّفات ثابتة وثلاثة مولَّدة. تُنشر إلى أندرويد كـresource-id عقدة الوصول، وهو ما يخاطبه XPath في Appium: login_button، go_to_sign_up_button، biometric_login_button، use_password_button، open_cart_button، hot_offers_list، open_map_button، save_favourite_button، reorder_button. والمولَّدة تحمل معرّف الطبق: add_to_cart_button_<mealId> وcart_line_quantity_<mealId>، مع cart_line_quantity_text_<mealId> مقابلًا لها من ValueKey — والأخيرة مفتاح لدارت فقط، فلا يراها Appium.
