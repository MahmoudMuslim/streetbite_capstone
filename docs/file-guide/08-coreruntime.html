08 lib/core/network + theme + usecase + utils — the scaffolding every feature reuses‏lib/core/network وtheme وusecase وutils — السقالة التي تعيد كل ميزة استخدامها

Ten files that carry no feature of their own but decide how every feature behaves: one HTTP client, four theme files, one use-case contract and three utility helpers.

Two structural promises are made here. The first is that transport knowledge stops at DioClient. The second is that core/theme never imports presentation: the glass flag travels as a ThemeExtension, so any widget can ask Theme.of(context) without knowing that a Cubit exists.

عشرة ملفات لا تملك ميزة واحدة لكنها تقرّر كيف تتصرف كل ميزة: عميل HTTP واحد، وأربعة ملفات سمة، وعقد حالات الاستخدام، وثلاثة أدوات مساعدة.

هنا وعدان بنيويان. الأول أن معرفة النقل تقف عند DioClient. والثاني أن core/theme لا يستورد presentation أبدًا: فعلم الزجاج يسافر كـ ThemeExtension، ليستطيع أي صنف واجهة أن يسأل Theme.of(context) وهو لا يدري أن Cubitًا موجودًا.

الموضع الوحيد في التطبيق المسموح له بمعرفة ما هو Dio.

Has

يحتوي

Does
Every transport concern is translated once, here: the interceptor rewrites any DioException into our own NetworkException with a short reason (timeout, offline, status_404, cancelled), and getJson() throws SerializationException when the body is not a JSON object. The optional dio constructor argument exists so a test can inject a mock without touching the network.
يفعل

minPasswordLength = 6، وRegExp للبريد، وRegExp للحرف الكبير، وrequired() وemail() وpassword() وconfirmPassword() وfullName().
Does
Every rule returns an ARB key such as validationPasswordShort or validationNameTwoWords, and the widget resolves it through the localizations object. That single decision is what lets the same validator speak English and Arabic at run time with zero hard-coded text in the UI, and it keeps the two-part rule from the requirements (“at least two words, starts with a capital”) in one testable place. required() takes the empty-state key as an argument so one helper serves every field.
يفعل
كل قاعدة ترجع مفتاح ARB مثل validationPasswordShort أو validationNameTwoWords»، والصنف الواجهة يحلّه عبر كائن التعريب. وهذا القرار الواحد هو ما يجعل المحقّق نفسه يتحدث العربية والإنجليزية وقت التشغيل بلا نص مثبّت في الواجهة، ويُبقي القاعدتين من المتطلبات («كلمتان على الأقل، ويبدأ بحرف كبير») في موضع واحد قابل للاختبار. وrequired() تأخذ مفتاح الحالة الفارغة وسيطًا فتخدم الأداة واحدة كل الحقول.
Needs
none — pure Dart, no imports
يحتاج
لا شيء — Dart خالصة بلا أي استيراد
Try it
Type mo as a full name and read the error: the field shows the localised validationNameTwoWords message; switch the app language mid-form and the same rule now speaks Arabic without re-validating. Then lower minPasswordLength to 3 and notice which test file complains first.
جرّب
اكتب mo اسمًا كاملًا واقرأ الخطأ: يعرض الحقل رسالة validationNameTwoWords المعرّبة؛ وبدّل لغة التطبيق في منتصف النموذج وتكلّم القاعدة نفسها بالعربية بلا إعادة تحقق. ثم خفّض minPasswordLength إلى 3 ولاحظ أي ملف اختبار يشتكي أولًا.
