02 streetbite_capstone/ — the ten files that define the project‏streetbite_capstone/ — الملفات العشرة التي تعرّف المشروع

Before a single Dart line runs, ten files decide what the project is: which packages it may use, how strictly it is analysed, how localisation is generated, which Firebase project it talks to and who may read its database. Three of them (pubspec.yaml, l10n.yaml, firestore.rules) are written and commented by hand; the rest are tool-managed.

قبل أن يُنفّذ أي سطر Dart، تقرّر عشرة ملفات ما هوْ المشروع: أي الحزم يحق له أن يستخدم، وكم يكون التحليل صارمًا، وكيف يُولّد التوطين، وأي مشروع Firebase يخاطبه، ومن يحق له قراءة بيانات قاعدة البيانات. وثلاثة منها (pubspec.yaml وl10n.yaml وfirestore.rules) كُتبت وشرحت يدويًّا، والباقي تُديره الأدوات.

streetbite_capstone/pubspec.yamlcfg

The package manifest: name, SDK floor, 20 runtime dependencies, 5 dev dependencies, icon config and asset folders.

بيان الحزم: الاسم وحدّ أدنى لإصدار SDK وعشرون اعتمادية وقت تشغيل وخمس للتطوير وإعداد الأيقونة ومجلدات الموارد.

Has
name: streetbite_capstone, version: 1.0.0+3, environment: sdk ^3.13.0; the dependency blocks (bloc, get_it, dio, shared_preferences, Firebase, maps/image_picker/local_auth/device_info_plus, intl, shimmer, cached_network_image, liquid_glass_widgets); dev_dependencies (bloc_test, mocktail, flutter_lints, flutter_launcher_icons); a flutter_launcher_icons block; and flutter: generate: true with assets/images/.
يحتوي
name: streetbite_capstone وversion: 1.0.0+3 وenvironment: sdk ^3.13.0؛ ثم كتل الاعتماديات (bloc وget_it وdio وshared_preferences وFirebase وmaps/image_picker/local_auth/device_info_plus وintl وshimmer وcached_network_image وliquid_glass_widgets)؛ وdev_dependencies (bloc_test وmocktail وflutter_lints وflutter_launcher_icons)؛ وكتلة flutter_launcher_icons؛ وflutter: generate: true مع assets/images/.
Does
Drives flutter pub get. generate: true is what makes flutter gen-l10n run as part of the build, and version feeds both the APK's versionName and Appium's expectations. The icon block explains, in comments, why iOS icons are off and why the adaptive foreground inset is 0.
يفعل
يقود flutter pub get. وgenerate: true هو ما يجعل flutter gen-l10n يعمل ضمن البناء، وversion يغذّي إصدار APK وتوقعات Appium. وتشرح التعليقات في كتلة الأيقونة لماذا أيقونات iOS مغلقة ولماذا هامش الطبقة الأمامية صفر.
Needs
The pub.dev registry, and pubspec.lock to reproduce the exact resolved versions.
يحتاج
سجل pub.dev، وpubspec.lock لإعادة إنتاج الإصدارات المحلولة نفسها.
Try it
Change version to 1.0.1+4, run flutter clean then flutter build apk --release, and watch the new number appear in android/app/build.gradle.kts via flutter.versionName.
جرّب
غيّر version إلى 1.0.1+4 ونفّذ flutter clean ثم flutter build apk --release وراقب الرقم الجديد يدخل android/app/build.gradle.kts عبر flutter.versionName.
streetbite_capstone/pubspec.lockcfg

The machine-written lockfile: every transitive package with its exact version and SHA.

ملف القفل الذي تكتبه الآلة: كل حزمة انتقالية بإصدارها المحدد وبصمتها.

Has
1,319 lines of packages: entries — 61 direct and transitive packages, each with dependency, description, source and version.
يحتوي
١٬٣١٩ سطرًا من مدخلات packages: — إحدى وأربعون حزمة مباشرة وانتقالية، لكل واحدة dependency وdescription وsource وversion.
Does
Makes the build reproducible: a teammate in another country gets byte-identical package versions, so a failure is a code failure, not a resolution failure.
يفعل
يجعل البناء قابلًا للتكرار: فيحصل زميل في بلد آخر على إصدارات مطابقة بايت-ببايت، فإذا فشل شيء فهو فشل شيفرة لا فشل حلّ تبعيات.
Needs
pubspec.yaml (it is derived, never hand-edited) and the pub cache.
يحتاج
pubspec.yaml (لأنه مستنبَط ولا يُحرَّر يدويًا) وذاكرة pub المؤقتة.
Try it
Delete pubspec.lock, run flutter pub get, and diff it with Git. That is exactly how much freedom a caret constraint gives the resolver.
جرّب
احذف pubspec.lock ونفّذ flutter pub get ثم قارنه بـ Git. هكذا بالضبط تعطي علامة (^) للمحلّل من حرية.
streetbite_capstone/analysis_options.yamlcfg

The static-analysis contract: which lint rules the codebase is held to.

عقد التحليل الثابت: أي قواعد lint ملزِمة لهذا الأساس الشيفري.

Has
include: package:flutter_lints/flutter.yaml, an analyzer.exclude list for build/, android/, ios/ and the other platform folders, and an empty (documented) rules: block.
يحتوي
include: package:flutter_lints/flutter.yaml، وقائمة analyzer.exclude لـ build/ وandroid/ وios/ وبقية مجلدات المنصات، وكتلة rules: فارغة وموثّقة.
Does
Turns "the code is clean" into a machine check: flutter analyze exits with no issues. Excluding the native folders matters because generated Java/Kotlin would otherwise flood the report.
يفعل
يحوّل عبارة «الشيفرة نظيفة» إلى فحص آلي: فيخرج flutter analyze بلا ملاحظات. وإستثناء المجلدات الأصلية مهم لأن شيفرة Java/Kotlin المولّدة كانت ستُغرق التقرير.
Needs
The flutter_lints dev dependency named in pubspec.yaml.
يحتاج
اعتمادية flutter_lints المذكورة في pubspec.yaml.
Try it
Uncomment prefer_single_quotes: true, run flutter analyze and read what it says about the existing code — then put it back. This is the cheapest way to feel what a lint rule does.
جرّب
أزل التعليق عن prefer_single_quotes: true ونفّذ flutter analyze واقرأ ما يقوله عن الشيفرة القائمة — ثم أعد كل شيء. أرخص طريقة لتحسّ بما تفعله قاعدة lint.
streetbite_capstone/l10n.yamlcfg

Instructions for flutter gen-l10n: where the translations live and where the class is written.

تعليمات flutter gen-l10n: أين reside الترجمة وأين تُكتب الطبقة المولّدة.

Has
Six keys: arb-dir: lib/l10n, template-arb-file: app_en.arb, output-localization-file: app_localizations.dart, output-class: AppLocalizations, output-dir: lib/l10n/generated, nullable-getter: false, use-escaping: true.
يحتوي
ستة مفاتيح: arb-dir: lib/l10n وtemplate-arb-file: app_en.arb وoutput-localization-file: app_localizations.dart وoutput-class: AppLocalizations وoutput-dir: lib/l10n/generated وnullable-getter: false وuse-escaping: true.
Does
Puts generated localisation inside lib/ so the compiled strings are visible in the source tree (and reviewable) instead of hidden in .dart_tool. nullable-getter: false removes every ! from call sites, and escaping enables {{placeholder}} interpolation.
يفعل
يضع توطين الطبقة المولّدة داخل lib/ فتكون السلاسل المترجمة مرئية في شجرة المصدر وقابلة للمراجعة بدل أن تختفي في .dart_tool. وnullable-getter: false يحذف كل ! من مواضع الاستدعاء، والتهريب يفعّل الاستبدال بـ {{placeholder}}.
Needs
lib/l10n/app_en.arb as the template and app_ar.arb as the translation.
يحتاج
lib/l10n/app_en.arb كقالب وapp_ar.arb كترجمة.
Try it
Add one key to app_en.arb only, run flutter gen-l10n, and read the error about the missing Arabic translation. That is the guard rail that stops the two locales drifting apart.
جرّب
أضف مفتاحًا واحدًا إلى app_en.arb وحدها ونفّذ flutter gen-l10n واقرأ خطأ الترجمة العربية الناقصة. ذلك هو الحاجز الذي يمنع تباعد اللغتين.
streetbite_capstone/firebase.jsoncfg

The Firebase CLI project pointer: which project, which apps, which rules file.

مؤشّر Firebase CLI إلى المشروع: أي مشروع وأي تطبيقات وأي ملف قواعد.

Has
firestore.rules path, and a flutter block naming Android project studio-3887960052-c09f5, its app id, the output path android/app/google-services.json and a dart: lib/firebase_options.dart entry.
يحتوي
مسار firestore.rules، وكتلة flutter تسمّي مشروع Android studio-3887960052-c09f5 ومعرف التطبيق ومخرج android/app/google-services.json ومدخل dart: lib/firebase_options.dart.
Does
Lets firebase deploy --only firestore:rules and flutterfire configure find the project without arguments.
يفعل
يسمح لـ firebase deploy --only firestore:rules وflutterfire configure بأن يجدا المشروع بلا وسائط.
Needs
The Firebase CLI (npm i -g firebase-tools) and login.
يحتاج
واجهة Firebase (npm i -g firebase-tools) وتسجيل الدخول.
Try it
Note the stale reference to lib/firebase_options.dart: that file was deliberately deleted when the app learned to start without Firebase, so the config is a historical record. Run flutterfire configure only if you intend to hand it back control.
جرّب
لاحظ الإشارة البالية إلى lib/firebase_options.dart: ذلك الملف حُذف عمدًا حين تعلّم التطبيق الإقلاع دون Firebase، فالإعداد سجل تاريخي. ولا تستدعِ flutterfire configure إلا إذا أردت إرجاع السيطرة إليه.
streetbite_capstone/firestore.rulescfg

Server-side authority over who may read or write each document.

السلطة من جانب الخادم على من يقرأ أو يكتب كل مستند.

Has
rules_version = '2', two functions (isSignedIn(), isOwner(uid)) and four match blocks: /users/{uid}, /users/{uid}/favourites/{mealId}, /orders/{uid} and /orders/{uid}/items/{orderId}.
يحتوي
rules_version = '2' ودالتان (isSignedIn() وisOwner(uid)) وأربع كتل match: /users/{uid} و/users/{uid}/favourites/{mealId} و/orders/{uid} و/orders/{uid}/items/{orderId}.
Does
Encodes one sentence — *a signed-in user may touch their own data and nothing else*. There is no list permission, no public read and no wildcard; anything unmatched fails closed. The header comment records the outage that produced it: the project was created with no rules file, so three features failed with PERMISSION_DENIED while Auth kept working.
يفعل
تُرمّز جملة واحدة — *المستخدم المسجّل يلمس بياناته وحدها ولا شيء غيرها*. لا إذن سرد ولا قراءة عامة ولا رمز تنصيص؛ وكل ما لا يطابق قاعدة يفشل مغلقًا. ويوثّق التعليق الرأسي العطل الذي أنتجها: المشروع أُنشئ بلا ملف قواعد، فتعطلت ثلاث ميزات بـ PERMISSION_DENIED بينما استمر Auth في العمل.
Needs
Deployment with the Firebase CLI. The client cannot bypass it: the rules run on Google's servers.
يحتاج
النشر بواجهة Firebase CLI. ولا يستطيع العميل التحايل عليها لأن القواعد تعمل على خوادم Google.
Try it
Temporarily change allow read, write: if isOwner(uid) to if isSignedIn(), deploy, and try to read another account's orders. Never do that on a production project.
جرّب
غيّر مؤقتًا allow read, write: if isOwner(uid) إلى if isSignedIn() وانشره وحاول قراءة طلبات حساب آخر. ولا تفعل ذلك أبدًا في مشروع إنتاجي.
streetbite_capstone/.metadatacfg

Flutter's record of the SDK the project was created with, for flutter migrate.

سجل Flutter عن SDK الذي أُنشئ به المشروع، لأجل flutter migrate.

Has
version.revision, channel: stable, project_type: app and the migration plan listing which platform folders the tool may touch.
يحتوي
version.revision وchannel: stable وproject_type: app وخطة migration التي تبيّن أي مجلدات أصلية يحق للأداة لمسها.
Does
Lets the Flutter tool tell you how far behind the project is and perform one-way migrations without breaking the native files.
يفعل
تتيح لأداة Flutter أن تخبرك بمدى تأخر المشروع وتنفّذ هجرة في اتجاه واحد دون كسر الملفات الأصلية.

يحتاج

جرّب
نفّذ flutter --version وقارن بصمته بالبصمة في هذا الملف. الفرق هو دين الترقية لديك.
streetbite_capstone/.gitignorecfg

The Flutter template's ignore list, with StreetBite's secrets added at the bottom.

قائمة استثناء قالب Flutter مع إضافات StreetBite للأسرار في الأسفل.

Has
Build output (/build/, .dart_tool/), IDE folders, coverage, symbol maps, and the project-specific lines: android/key.properties, android/app/google-services.json, ios/Runner/GoogleService-Info.plist, manual_qa/screenshots/raw/.
يحتوي
مخرجات البناء (/build/ و.dart_tool/) ومجلدات المحرّر والتغطية وخرائط الرموز، والسطور الخاصة بالمشروع: android/key.properties وandroid/app/google-services.json وios/Runner/GoogleService-Info.plist وmanual_qa/screenshots/raw/.
Does
Keeps credentials out of the submission while keeping everything needed to rebuild in it. The last four lines are StreetBite's own additions and are the reason a fresh clone builds without a Firebase project.
يفعل
يبقي بيانات الاعتماد خارج التسليم مع الإبقاء على كل ما يلزم لإعادة البناء فيه. والسطور الأربعة الأخيرة إضافة StreetBite نفسها، وهي سبب بناء أي استنساخ جديد بلا مشروع Firebase.
Needs
Git.
يحتاج
أداة Git وحدها.
Try it
Run git check-ignore -v streetbite_capstone/android/key.properties. Seeing the rule that caught it is how you prove no API key was ever committed.
جرّب
نفّذ git check-ignore -v streetbite_capstone/android/key.properties. ورؤية القاعدة التي التقطته هي كيف تُثبت أن مفتاح API لم يُرفَع إلى Git أبدًا.
streetbite_capstone/.flutter-plugins-dependenciescfg

A generated cache of which native plugin code the app needs, per platform.

ذاكرة مولَّدة للشيفرة الأصلية التي تحتاجها المنصات لكل إضافة.

One JSON line listing the Android/iOS plugin packages and their dependency graph (firebase_core → firebase_auth → cloud_firestore, google_maps_flutter, local_auth_android, …).

سطر JSON واحد يسمّي حزم إضافات Android/iOS ورسم اعتمادياتها (firebase_core ثم firebase_auth ثم cloud_firestore وgoogle_maps_flutter وlocal_auth_android…).

نفّذ flutter pub get وراقب إعادة كتابته — ثم اشرح لماذا لا يجوز لملف مولَّد تلقائيًا أن يكون في Git.

How this document was made. Written against commit 07b200f. Every card was produced by reading the file it describes; the line counts, declaration names and import lists are extracted from the source tree by _audit/imports.py, and _audit/build_guide.py refuses to build if a card points at a Dart file that no longer exists. Nothing here is remembered from a previous draft.

Companion documents. docs/code-doc/index.html explains the concepts (architecture, state, errors, security) layer by layer; this guide answers the other question — what is each file for. docs/StreetBite_Capstone_Report_EN-AR.pptx is the slide deck for the defence itself.

Language. Both columns are on by default; the sidebar switches to English or Arabic only. Paths, identifiers and code are never translated, because Either<Failure, List<MealEntity>> reads the same in either language.

كيف صُنعت هذه الوثيقة. كُتبت عند الالتزام 07b200f. وكل بطاقة نُقلت بعد قراءة الملف الموصوف؛ وأعداد الأسطر وأسماء التصريحات وقوائم الاستيراد تُستخرج من شجرة المصدر بواسطة _audit/imports.py، و_audit/build_guide.py يرفض البناء إذا أشارت بطاقة إلى ملف Dart لم يعد موجودًا. ولا شيء هنا من الاستذكار.

الوثائق المكمّلة. يشرح docs/code-doc/index.html المفاهيم (المعمارية، الحالة، الأخطاء، الحماية) طبقة طبقة؛ أما هذا الدليل فيجيب عن السؤال الآخر: ما وظيفة كل ملف. وملف docs/StreetBite_Capstone_Report_EN-AR.pptx هو العرض التقديمي للمناقشة.

اللغة. العمودان ظاهران افتراضيًا، ويحوّلهما الشريط الجانبي إلى الإنجليزية أو العربية وحدها. ولا تُترجَم المسارات والمعرّفات والشفرة أبدًا، لأن Either<Failure, List<MealEntity>> تُقرأ بالشكل نفسه في اللغتين.
