07 lib/core/constants + lib/core/error — the vocabulary of the whole app‏lib/core/constants وlib/core/error — مفردات التطبيق كله

Six files declare the words every other layer repeats: the route names, the endpoints and preference keys, the category table, and the two halves of the error contract.

The rule StreetBite follows — and can be examined on — is that a failure is a value, never an uncontrolled event. Either carries it out of the data layer, the Failure types classify it, messageKey localises it, and the three low-level exceptions are consumed before they can reach a widget.

ستة ملفات تعلن الكلمات التي تكرّرها كل الطبقات الأخرى: أسماء المسارات، والروابط ومفاتيح التفضيلات، وجدول التصنيفات، وشقّا عقد الخطأ.

القاعدة التي يتبعها StreetBite ويمكن محاسبته عليها أن الفشل قيمة ولا يكون حدثًا خارج السيطرة أبدًا. يحمّله Either خارج طبقة البيانات، وتُصنِّفه أصناف Failure، و«messageKey» يعرّبه، والاستثناءات الثلاثة منخفضة المستوى تُستهلك قبل أن تصل إلى أي صنف واجهة.

streetbite_capstone/lib/core/constants/app_categories.dartcore90 lines

One table of the seven menu categories, used by both the Home chips and the Browse grid.

جدول واحد للتصنيفات السبعة يقرأه شريط الرئيسية وشبكة تبويب التصفح.

Has
Each AppCategory carries an icon, an ARB labelKey, the TheMealDB apiCategory it filters on and optional alsoMatches aliases; all holds the seven entries, matches() does the case-insensitive test and byApiCategory() maps an API answer back to a chip.
يحتوي
كل AppCategory يحمل icon وlabelKey من ARB وapiCategory الخاص بـ TheMealDB وalsoMatches الاختياري؛ وall يضم السبعة، وmatches() يجري مقارنة غير حساسة لحالة الأحرف، وbyApiCategory() يعيد اسم الإجابة إلى زرّ.
Does
Kills a real duplication bug that the file's own comment records: the chips and the grid used to keep separate copies of the list, which is how the Home chips became dead decorations while Browse filtered. Vegetarian also matches Vegan so tapping it does not hide dishes a user expects to see; Pizza filters on its literal name because TheMealDB has no such category, and honestly lands on the empty state instead of silently showing everything. Labels stay ARB keys, so the same table speaks both languages.
يفعل
يقتل تكرارًا حقيقيًا يوثّقه تعليق الملف نفسه: الشريط والشبكة كانا يحفظان نسختين من القائمة، فصارت أزرار الرئيسية زينة لا تعمل بينما التصفح يفلتر فعلًا. وVegetarian يطابق Vegan أيضًا حتى لا يخفي أطباقًا يتوقعها المستخدم، وPizza يفلتر باسمه الحرفي لأن TheMealDB لا يملك هذا التصنيف فيستقرّ بصدق على حالة «لا أطباق» بدل إظهار كل شيء. والأسماء تبقى مفاتيح ARB فيتحدث الجدول باللغتين.
Needs
flutter/material.dart for the icons and domain/entities/meal_entity.dart for the matches() test — the only upward reach allowed, because it is a read of a domain value.
يحتاج
flutter/material.dart للأيقونات وdomain/entities/meal_entity.dart لأجل matches() — وهي الطلعة الوحيدة للأعلى المسموح بها لأنها تقرأ قيمة من domain.
Try it
Add an eighth AppCategory reusing a labelKey that already exists, restart, and count the chips on Home against the tiles on Browse: both grew from that one line. That is the proof the single table is worth.
جرّب
أضِف AppCategory ثامنًا معيدًا استخدام labelKey موجود، وأعد التشغيل وعدّ الأزرار في الرئيسية مقابل المربّعات في التصفح: كلاهما زاد من ذلك السطر الواحد. هذا هو الدليل على قيمة الجدول الواحد.
streetbite_capstone/lib/core/constants/app_constants.dartcore63 lines

The single source of truth for every value that would otherwise be a magic literal.

مصدر الحقيقة الوحيد لكل قيمة كان يمكن أن تكون رقمًا سحريًا مكررًا.

Has
appName, baseUrl, mealsEndpoint, hotOffersEndpoint, cacheMealsKey, cacheHotOffersKey, the three Firestore collection names, userFavouritesSubCollection, networkTimeout, orderActiveWindow, allowOfflineFirebaseFallback, the three QA demo credentials, vendorCount and baseMealPrice.
يحتوي
appName وbaseUrl وmealsEndpoint وhotOffersEndpoint وcacheMealsKey وcacheHotOffersKey وأسماء مجموعات Firestore الثلاث وuserFavouritesSubCollection وnetworkTimeout وorderActiveWindow وallowOfflineFirebaseFallback وثلاثة بيانات اعتماد حساب التجربة وvendorCount وbaseMealPrice.
Does
Makes the schema and the tuning auditable on one screen: the 20-second networkTimeout is what the UI hangs against, the 45-minute orderActiveWindow is the only rule that decides whether an order still belongs to “Current”, and allowOfflineFirebaseFallback is the documented production switch — set it to false and Firebase failures surface to the user instead of degrading quietly. baseMealPrice exists because TheMealDB publishes no prices, and the price is derived from the meal id so a cached meal keeps the same number across launches.
يفعل
يجعل المخطط والضبط قابلَين للمراجعة في شاشة واحدة: networkTimeout بعشرين ثانية هو ما تتوقف الواجهة عنده، وorderActiveWindow بخمس وأربعين دقيقة هو القاعدة الوحيدة التي تقرّر إن كان الطلب ما زال «جارياً»، وallowOfflineFirebaseFallback هو مفتاح الإنتاج الموثّق — اجعله false لتظهر أعطال Firebase للمستخدم بدل أن تُطوى في صمت. وbaseMealPrice موجود لأن TheMealDB لا ينشر أسعارًا، والسعر مشتق من معرّف الصحن فيبقى ثابتًا بين الإقلاع حتى مع الذاكرة المؤقتة.
Needs
const AppConstants._(); makes it unconstructable, and every member is static const, so nothing is recomputed at run time. It imports nothing, which is why any layer may read it.
يحتاج
const AppConstants._(); يمنع إنشاء نسخة منه، وكل عضو static const فلا يُعاد حسابه وقت التشغيل. ولا يستورد شيئًا، ولهذا تقرأه كل الطبقات.
Try it
Raise orderActiveWindow to Duration(hours: 24), place an order and reopen the Orders tab: it now stays in the “Current” block. Then set allowOfflineFirebaseFallback to false and rename google-services.json — the app reports the failure instead of hiding it.
جرّب
ارفع orderActiveWindow إلى Duration(hours: 24) وأنشئ طلبًا وأعد فتح تبويب الطلبات: يبقى في كتلة «الجارية». ثم اجعل allowOfflineFirebaseFallback يساوي false وأعد تسمية google-services.json؛ يعلن التطبيق عن العطل ولا يخفيه.
streetbite_capstone/lib/core/constants/app_routes.dartcore27 lines

The route-name table: one constant per navigable screen, plus the four tab indices.

قائمة أسماء المسارات: ثابت لكل شاشة يمكن الانتقال إليها مع فهرس التبويبات الأربعة.

Has
splash = '/', login, biometricLogin, signUp, home, mealDetails, cart, orderConfirmation, orderDetails, vendorMap, profile, settings, and tabHome/tabBrowse/tabOrders/tabProfile.
يحتوي
splash = '/' وlogin وbiometricLogin وsignUp وhome وmealDetails وcart وorderConfirmation وorderDetails وvendorMap وprofile وsettings، وtabHome وtabBrowse وtabOrders وtabProfile.
Does
Navigation is written as AppRoutes.cart rather than a repeated string literal, so a renamed route fails at compile time instead of opening a blank page at run time. splash is deliberately '/' because MaterialApp.initialRoute starts there, and the tab indices are constants so the shell and the deep-link handler can never disagree about which index means Home.
يفعل
الانتقال يُكتب AppRoutes.cart لا نصًا مكررًا، فأي مسار تُعاد تسميته يفشل وقت الترجمة بدل أن يفتح صفحة بيضاء أثناء التشغيل. وsplash هو '/' عمدًا لأن initialRoute يبدأ منه، والأرقام الأربعة ثابتة حتى لا يختلف الغلاف ومعالج الارتباط العميق على أيّ فهرس هو الرئيسية.
Needs
none — pure Dart, no imports
يحتاج
لا شيء — Dart خالصة بلا أي استيراد
Try it
Rename cart to /basket here and run flutter analyze: the call sites keep compiling because they use the constant, and only this one line changes — that is the entire value of the file. Now imagine the same route as twelve string literals.
جرّب
أعد تسمية cart إلى /basket هنا ونفّذ flutter analyze: مواقع النداء تواصل الترجمة لأنها تستخدم الثابت، ولا يتغيّر إلا هذا السطر — وهذه هي قيمة الملف كلها. ثم تخيّل المسار نفسه اثني عشر نصًا مكررًا.
streetbite_capstone/lib/core/error/either.dartcore63 lines

The two-branch result type every fallible function in the app returns.

نوع النتيجة ذو الفرعين الذي ترجعه كل دالة قابلة للفشل في التطبيق.

Has
sealed class Either<L, R> with const factory Either.left(...) and const factory Either.right(...), plus fold(), map(), isLeft and valueOrNull; final class Left and final class Right carry the value.
يحتوي
sealed class Either<L, R> مع const factory Either.left(...) وconst factory Either.right(...)، ومع fold() وmap() وisLeft وvalueOrNull؛ ويحمل final class Left وfinal class Right القيمة.
Does
This file is the answer to “why not just throw?”. Exceptions are invisible to the type system: a repository can forget one and the compiler stays quiet. With a sealed result the caller is forced to handle the failure branch, and fold() collapses both branches into one expression so no Cubit needs an if. Because the class is sealed, the switch expressions are exhaustiveness-checked: add a third branch and every switch in the app stops compiling until it is handled.
يفعل
هذا الملف هو الجواب عن «لماذا لا نرمي استثناء؟». الاستثناءات غير مرئية لنظام الأنواع: قد ينسى مستودع واحدًا ويظل المترجم صامتًا. ومع نتيجة sealed يُجبَر المستدعي على معالجة فرع الفشل، ويختصر fold() الفرعين في تعبير واحد فلا يحتاج أي Cubit إلى if. ولأن الصنف sealed تُفحص تعبيرات switch فيه لاستيفاء كل الحالات: أضِف فرعًا ثالثًا ويتوقف كل تعبير switch في التطبيق عن الترجمة حتى تعالجه.
Needs
none — pure Dart, no imports
يحتاج
لا شيء — Dart خالصة بلا أي استيراد
Try it
In MealsCubit, replace result.fold(onFailure: emit, onSuccess: ...) with a bare result.valueOrNull and read the analyzer: no complaint — and that silence is exactly what this file exists to remove. Then declare final class Both<L, R> extends Either<L, R> and watch fold and map go red.
جرّب
في MealsCubit استبدل result.fold(onFailure: emit, onSuccess: ...) بـ result.valueOrNull المجردة واقرأ محلل الأكواد: لا شكوى — وهذا الصمت هو بعينه ما وُجد هذا الملف لإزالته. ثم اعلن final class Both<L, R> extends Either<L, R> وشاهد fold وmap يحمرّان.
streetbite_capstone/lib/core/error/exceptions.dartcore35 lines

The three low-level exceptions data sources may throw — and the boundary they never cross.

الاستثناءات الثلاثة منخفضة المستوى التي قد ترميها مصادر البيانات — والحدّ الذي لا تتجاوزه أبدًا.

Has
NetworkException(message, {statusCode}), SerializationException(message) and the argument-less FirestoreNotAvailableException; all three implements Exception with a readable toString().
يحتوي
NetworkException(message, {statusCode}) وSerializationException(message) وFirestoreNotAvailableException بلا وسائط؛ الثلاثة implements Exception مع toString() مقروءة.
Does
Exceptions are the right tool inside the data layer: a Dio interceptor and a Firestore guard have no return channel, so they must throw. The contract is that every repository catches them on the way out and maps them onto a Failure. That is why the UI can never see a DioException, and why a transport detail never becomes a sentence shown to a user.
يفعل
الاستثناء أداة صحيحة داخل طبقة البيانات: معترض Dio وحارس Firestore لا يجد قناة إرجاع، فترميان. والعقد أن كل مستودع يلتقطها في طريق الخروج ويحوّلها إلى Failure. ولهذا لا ترى الواجهة DioException أبدًا، ولا يتحوّل تفصيل نقل إلى جملة تُعرض على المستخدم.
Needs
none — pure Dart, no imports
يحتاج
لا شيء — Dart خالصة بلا أي استيراد
Try it
Break the contract on purpose: let NetworkException escape MealRemoteDataSource without a catch, then run with the device in airplane mode. The Home feed still shows its friendly error panel — proof that MealRepositoryImpl and not the screen is doing the mapping.
جرّب
اخرق العقد عمدًا: دع NetworkException يفلت من MealRemoteDataSource بلا التقاط، وشغّل الجهاز في وضع الطيران. تبقي الرئيسية تعرض لوحة الخطأ اللطيفة — والدليل أن MealRepositoryImpl هو من يحوّل لا الشاشة.
streetbite_capstone/lib/core/error/failures.dartcore48 lines

The five typed failures that reach the UI, each already carrying its localised message key.

الأخطاء الخمسة الموسومة التي تصل إلى الواجهة، كل واحد يحمل مفتاح رسالته المعرّبة.

Has
sealed class Failure implements Exception with a messageKey and an optional logging-only details, then ServerFailure, CacheFailure, ValidationFailure, AuthFailure and CancelledFailure.
يحتوي
sealed class Failure implements Exception فيه messageKey وdetails اختياري للسجل فقط، ثم ServerFailure وCacheFailure وValidationFailure وAuthFailure وCancelledFailure.
Does
The default keys are hard-coded to ARB entries (failureNetwork, failureCache, failureCancelled) while ValidationFailure and AuthFailure take the key as a constructor argument, because their message depends on which field or which Firebase error code produced them. Since Failure also implements Exception, the same value can be thrown in a genuinely exceptional path or returned through Either without splitting the model. details never reaches the screen — that separation is what keeps stack traces out of user-facing text.
يفعل
المفاتيح الافتراضية مثبّتة على مدخلات ARB هي (failureNetwork وfailureCache وfailureCancelled)، بينما يأخذ ValidationFailure وAuthFailure المفتاحَ وسيطًا في الباني لأن رسالتهما تعتمد على الحقل أو على رمز خطأ Firebase الذي أنتجها. ولأن Failure ينفّذ Exception أيضًا، يمشي القيمة نفسها في مسار استثنائي حقيقي أو تُرجع عبر Either دون تقسيم النموذج. وdetails لا يصل إلى الشاشة أبدًا — وهذا الفصل هو ما يبقي آثار المكدّس خارج نص المستخدم.
Needs
none — pure Dart, no imports
يحتاج
لا شيء — Dart خالصة بلا أي استيراد
Try it
Add a PaymentFailure extends Failure with a new messageKey, add that key to both ARB files, and surface it from a cart validation. Then run python scripts/check_unused_arb.py to prove no key was left orphaned.
جرّب
أضِف PaymentFailure extends Failure بمفتاح رسالة جديد، وأضِف المفتاح إلى ملفَي ARB، وأظهره من تحقق السلة. ثم نفّذ python scripts/check_unused_arb.py لتثبت أن لا مفتاح بقي يتيمًا.

How this document was made. Written against commit 07b200f. Every card was produced by reading the file it describes; the line counts, declaration names and import lists are extracted from the source tree by _audit/imports.py, and _audit/build_guide.py refuses to build if a card points at a Dart file that no longer exists. Nothing here is remembered from a previous draft.

Companion documents. docs/code-doc/index.html explains the concepts (architecture, state, errors, security) layer by layer; this guide answers the other question — what is each file for. docs/StreetBite_Capstone_Report_EN-AR.pptx is the slide deck for the defence itself.

Language. Both columns are on by default; the sidebar switches to English or Arabic only. Paths, identifiers and code are never translated, because Either<Failure, List<MealEntity>> reads the same in either language.

كيف صُنعت هذه الوثيقة. كُتبت عند الالتزام 07b200f. وكل بطاقة نُقلت بعد قراءة الملف الموصوف؛ وأعداد الأسطر وأسماء التصريحات وقوائم الاستيراد تُستخرج من شجرة المصدر بواسطة _audit/imports.py، و_audit/build_guide.py يرفض البناء إذا أشارت بطاقة إلى ملف Dart لم يعد موجودًا. ولا شيء هنا من الاستذكار.
