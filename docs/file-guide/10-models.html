10 ‏lib/data/models — the seven files that own serialisation‏lib/data/models — السبعة الملفات التي تملك التسلسل

Seven models, and one rule repeated in every one of them: the model owns serialisation, the entity owns behaviour. That split is what makes it impossible for Map<String, dynamic> to leak into a widget, and it is the reason swapping TheMealDB for another API would never reach the UI.

Two of the seven (MealModel, UserModel) extend their entity, so a model can be handed to the domain unchanged. The other five keep their distance and convert with fromEntity() / toEntity() — a deliberate difference explained on the cards below.

سبعة نماذج، وقاعدة واحدة تتكرر في كل واحد منها: النموذج يملك التسلسل، و الكيان يملك السلوك. وهذا الفصل هو ما يستحيل معه أن يتسرب Map<String, dynamic> إلى صنف واجهة، وهو سبب أن استبدال TheMealDB بغيره لن يصل إلى الواجهة أبدًا.

اثنان من السبعة (MealModel وUserModel) يمتدان كيانهما فيسلَّم النموذج إلى النطاق بلا تغيير. والخمسة الباقية تحفظ مسافتها وتحوّل بـ fromEntity() وtoEntity() — فرق موثّق في البطاقات أدناه.

streetbite_capstone/lib/data/models/meal_model.dartdata153 lines

The most defensive parser in the app: one class, two completely different input shapes.

أكثر محلل احتياطًا في التطبيق: صنف واحد، وشكلا إدخال مختلفان تمامًا.

Has
Nine public document keys (idKey … youtubeKey), eight private _api… constants, fromApiJson(), fromJson(), fromEntity(), toJson(), the static priceForId(), and the private cleaners _clean(), _nullableString(), _toDouble(), _parseTags().
يحتوي
تسعة مفاتيح مستند عامة (idKey إلى youtubeKey)، وثمانية ثوابت خاصة _api…، وfromApiJson() وfromJson() وfromEntity() وtoJson()، والدالة الثابتة priceForId()، وأدوات التنظيف الخاصة _clean() و_nullableString() و_toDouble() و_parseTags().
Does
The API speaks in strMeal and idMeal while the app's own cache and Firestore documents speak name and id, so two factories exist rather than one with flags inside it. Every accessor has a fallback: _clean() treats the literal strings null and Unknown as absent, _parseTags() accepts a comma-separated string or a real list, and _toDouble() parses what it can and lands on 8.99 otherwise. Because MealModel extends MealEntity there is no mapping step between the data source and the repository. priceForId() exists because TheMealDB publishes no prices: it sums the id's code units and maps the result into the $6.99–$24.99 band used by the design, so the same dish always costs the same across launches, and a cached menu agrees with a freshly fetched one.
يفعل
تنطق الواجهة البرمجية بـ strMeal وidMeal بينما ينطق مخزن التطبيق ووثائق Firestore بأسماء من نوع name وid، فوُجد بانيين لا باني واحد تُحشى فيه الرايات. ولكل مستخرج بديل: يعامل _clean() النصين الحرفيين null وUnknown كغياب، وتقبل _parseTags() نصًا مفصولًا بفواصل أو قائمة حقيقية، وتحلل _toDouble() ما تقدر عليه وتستقر على 8.99 فيما عدا ذلك. ولأن MealModel extends MealEntity لا توجد خطوة تحويل بين مصدر البيانات والمستودع. وpriceForId() موجودة لأن TheMealDB لا ينشر أسعارًا: تجمع وحدات المعرّف ثم تضع الناتج في نطاق من 6.99 إلى 24.99 دولارًا استخدمه التصميم، فيبقى صحن واحد بسعر واحد بين الإقلاعات، ويتفق المخزون مع ما يُجلَّب جديدًا.

streetbite_capstone/lib/data/models/user_model.dartdata152 lines

The Builder pattern, used because four different places know four different amounts about the same user.

نمط الباني، لأنه يُستخدم حيث تعرف أربعة مواضع مقادير مختلفة من المستخدم نفسه.

Has
UserModel extends UserEntity; six document keys including passwordHashKey, which belongs only to the local store; the static builder(); fromJson(), fromFirebase(), fromEntity(), toJson() and an overridden copyWith(); plus the UserBuilder class with five fluent setters and build().
يحتوي
UserModel extends UserEntity؛ وستة مفاتيح مستند منها passwordHashKey الذي يخص المخزن المحلي وحده؛ والدالة الثابتة builder()؛ وfromJson() وfromFirebase() وfromEntity() وtoJson() وcopyWith() معاد تعريفها؛ وصنف UserBuilder بخمس دوال متسلسلة وbuild().
Does
A Firebase sign-up knows uid, email and display name; a Firestore document adds a photo URL; the local fallback knows an email, a digest and a name; a restored session may know only uid and email. One constructor with eight required parameters would force each of those call sites to invent values it does not have, so every path goes through the builder and leaves the rest at defaults — the builder is where partial knowledge is legitimate. photoUrl("") normalises to null so an empty string can never be written to Firestore and read back as a real URL. copyWith() is overridden to return a UserModel, not the parent type, so a widened entity never degrades on the first edit. The class doc also records why no caching is added to the builder: at most one user is built per session.
يفعل
تسجيل Firebase يعرف المعرّف والبريد واسم العرض؛ ووثيقة Firestore تزيد رابط الصورة؛ والمخزن المحلي يعرف البريد والبصمة والاسم؛ والجلسة المستعادة قد تعرف المعرّف والبريد فقط. ولو كان الباني بثمانية وسائط إلزامية لأُجبر كل موضع على اختراع قيم لا يعرفها، فكل مسار يمر بالباني وتبقى البقية على بدائلها — وهذا يجعل المعرفة الجزئية مشروعة. وتحول photoUrl("") النص الفارغ إلى null فلا تُكتب سلسلة فارغة في Firestore وتُقرأ رابطًا حقيقيًا. وأعيد تعريف copyWith() لترجع UserModel لا النوع الأبوي، فلا يتدهور كيان موسّع عند أول تعديل. ويوثق التعليق سبب عدم إضافة تخزين مؤقت إلى الباني: مستخدم واحد يُبنى في الجلسة كحد أقصى.

streetbite_capstone/lib/data/models/order_model.dartdata113 lines

The order document: everything the Orders screen needs, in one read.

مستند الطلب: كل ما تحتاجه شاشة الطلبات في قراءة واحدة.

Has
Nine document keys plus the redundant totalKey, the itemsSubCollection constant that names the path orders/{uid}/items/{orderId}, nine fields, a total getter, fromJson(), fromEntity(), toJson() and toEntity().
يحتوي
تسعة مفاتيح مستند مع totalKey الزائد عن الحاجة، وثابت itemsSubCollection الذي يسمي المسار orders/{uid}/items/{orderId}، وتسعة حقول، وقارئ total، وfromJson() وfromEntity() وtoJson() وtoEntity().
Does
Cart lines and the payment snapshot are written inline inside the order document instead of into sub-collections, so the Orders screen renders from a single query rather than one read per item. Every reader is defensive: a missing list becomes an empty one, absent numbers become 0, an unparsable placedAt falls back to DateTime.now(), and an unknown status string resolves to OrderStatus.past through OrderStatus.fromKey rather than throwing. toJson() writes the computed total as well as its three components: the document is then self-describing for a receipt or a security-rule check, even though the getter could always recompute it. Note this model does not extend OrderEntity — an order embeds a payment strategy, so the conversion goes through PaymentModel on the way out and back.
يفعل
تُكتب أسطر السلة ولقطة الدفع داخل مستند الطلب لا في مجموعات فرعية، فتعرض الشاشة من استعلام واحد لا من قراءة لكل صحن. وكل قارئ محتاط: القائمة الغائبة فارغة، والأعداد الغائبة صفر، وplacedAt غير القابل للتحويل يستقر على DateTime.now()، وحالة مجهولة الاسم ترجع OrderStatus.past عبر OrderStatus.fromKey بدل أن ترمي. ويكتب toJson() total المحسوب مع مكوناته الثلاثة فيكون المستند واصفًا لنفسه في إيصال أو في فحص قاعدة حماية، وإن كان القارئ قادرًا على حسابه دائمًا. ولاحظ أن هذا النموذج لا يمتد OrderEntity — لأن الطلب يضم استراتيجية دفع، فالتحويل يمر بـ PaymentModel ذهابًا وإيابًا.

streetbite_capstone/lib/data/models/payment_model.dartdata38 lines

A two-field snapshot of a strategy object — the smallest file with the clearest job.

لقطة من حقلين لكائن استراتيجية — أصغر ملف بأوضح وظيفة.

Has
typeKey, last4Key, two fields, fromJson(), fromEntity(), toJson() and toEntity().
يحتوي
typeKey وlast4Key وحقلان، وfromJson() وfromEntity() وtoJson() وtoEntity().
Does
The document never stores a PaymentMethod object, only the discriminator and, for a card, the last four digits — fromEntity() reaches for last4 only after an is CardPayment test. toJson() uses a collection-if, so a cash order does not carry an empty last4 field at all. toEntity() rehydrates the strategy from the enum with a switch, which is what keeps the SOLID contract intact across the wire: the checkout screen gets a real polymorphic object back, not a string. No full card number is ever representable here — PCI-safe by construction, not by policy.
يفعل
لا يخزن المستند كائن PaymentMethod أبدًا، بل المميّز وآخر أربعة أرقام من البطاقة فقط — وfromEntity() يمد يده إلى last4 بعد اختبار is CardPayment فقط. ويستخدم toJson() شرطًا داخل المجموعة فلا يحمل طلب نقدًا حقل last4 فارغًا أصلًا. وتعيد toEntity() بناء الاستراتيجية من التعداد بتعبير switch، وهذا ما يبقي عقد SOLID سليمًا عبر السلك: شاشة الدفع تستلم كائنًا متعددًا حقيقيًا لا نصًا. ولا يمكن تمثيل رقم بطاقة كامل هنا أبدًا — سلامة PCI بالبناء لا بالسياسة.

streetbite_capstone/lib/data/models/favourite_model.dartdata36 lines

A saved meal whose document is the meal.

صحن محفوظ مستنده هو الصحن.

Has
savedAtKey, a MealModel, a DateTime, fromJson(), fromEntity(), toJson() and toEntity().
يحتوي
savedAtKey وMealModel وDateTime وfromJson() وfromEntity() وtoJson() وtoEntity().
Does
toJson() spreads the meal's own map into the document root and adds one timestamp, so users/{uid}/favourites/{mealId} is simultaneously a valid meal record and a favourite record — the document id is the meal id, which is what lets FavouriteRepositoryImpl toggle by existence check alone. A missing or unparsable savedAt becomes now, so one malformed heart cannot break the whole favourites list. The price of the flattening is that fromJson() must hand MealModel.fromJson the same map, relying on the meal keys living at the root.
يفعل
ينشر toJson() خريطة الصحن نفسها في جذر المستند ويزيد طابعًا زمنيًا واحدًا، فيكون users/{uid}/favourites/{mealId} سجل صحن صالحًا وسجل مفضلة في الوقت ذاته — ومعرّف المستند هو معرّف الصحن، وهذا ما يسمح لـ FavouriteRepositoryImpl بالتبديل اعتمادًا على الوجود وحده. وsavedAt التالف يصير «الآن» فلا يفسد قلب واحد قائمة المفضلة كلها. وثمن الدمج أن على fromJson() أن تُسلَّم الخريطة نفسها إلى MealModel.fromJson معتمدًا على أن مفاتيح الصحن في الجذر.

streetbite_capstone/lib/data/models/vendor_model.dartdata85 lines

The map marker's payload: nine flat fields, no behaviour.

حمولة دبوس الخريطة: تسعة حقول مسطحة بلا سلوك.

Has
Document keys for id, name, cuisine, rating, lat, lng, distanceKm, thumbnailUrl and address, each mirrored as a field, plus fromJson(), fromEntity(), toJson() and toEntity().
يحتوي
مفاتيح مستند لـ id وname وcuisine وrating وlat وlng وdistanceKm وthumbnailUrl وaddress، وكلٌّ منها مرآة لحقل، مع fromJson() وfromEntity() وtoJson() وtoEntity().
Does
Nothing is computed here: the model is a carrier between the seed list and the domain entity. It is also the shape a future Firestore vendors collection would have to match, which is why latitude and longitude are separate numbers rather than a GeoPoint — the swap to a real geo-query is a data-source change, and the model is the contract that stays stable through it. Two constants hide shorter wire names: latitudeKey is lat and longitudeKey is lng, which is precisely why call sites use the constant instead of typing the string.
يفعل

How this document was made. Written against commit 07b200f. Every card was produced by reading the file it describes; the line counts, declaration names and import lists are extracted from the source tree by _audit/imports.py, and _audit/build_guide.py refuses to build if a card points at a Dart file that no longer exists. Nothing here is remembered from a previous draft.

Companion documents. docs/code-doc/index.html explains the concepts (architecture, state, errors, security) layer by layer; this guide answers the other question — what is each file for. docs/StreetBite_Capstone_Report_EN-AR.pptx is the slide deck for the defence itself.

Language. Both columns are on by default; the sidebar switches to English or Arabic only. Paths, identifiers and code are never translated, because Either<Failure, List<MealEntity>> reads the same in either language.
