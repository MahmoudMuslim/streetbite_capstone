09 ‏lib/data/datasources + lib/data/services — the only files that touch the outside world‏lib/data/datasources وlib/data/services — الملفات الوحيدة التي تلمس الخارج

Eight files stand between StreetBite and everything it does not control: Firebase Auth, Cloud Firestore, TheMealDB over HTTP, shared_preferences and the biometric hardware. Nothing else in lib/ imports those packages.

Each one has exactly one job: talk to one external system and hand back a model or a typed exception. They know nothing about caching policy, nothing about formatting, and nothing about widgets — which is why a repository can combine two of them, and why a test can replace either one.

ثمانية ملفات تقف بين StreetBite وكل ما لا يتحكّم به: Firebase Auth وCloud Firestore وTheMealDB عبر HTTP وshared_preferences وعتاد القياس البيومتري. لا شيء في lib/ سواها يستورد تلك الحزم.

لكل ملف عمل واحد بعينه: مخاطبة نظام خارجي واحد وإرجاع نموذج أو استثناء موسوم. فلا تعرف عن سياسة التخزين شيئًا، ولا عن التنسيق، ولا عن أصناف الواجهة — ولهذا يستطيع مستودع أن يجمع اثنين منها، وتستطيع اختبار أن تستبدل أيًّا منهما.

streetbite_capstone/lib/data/datasources/auth_local_data_source.dartdata151 lines

The on-device account store that keeps sign-up, login and session restore testable when Firebase cannot be reached.

مخزن الحسابات على الجهاز الذي يبقي التسجيل والدخول واستعادة الجلسة قابلة للاختبار حين لا يمكن الوصول إلى Firebase.

Has
Three preference keys (_usersKey, _sessionKey, _biometricSignInKey), the biometricSignInEnabled getter and its setter, ensureDemoAccount(), findByEmail(), createUser(), verifyCredentials(), saveSession(), readSession(), clearSession(), and the static hash() digest.
يحتوي
مفاتيح تفضيلات ثلاثة هي _usersKey و_sessionKey و_biometricSignInKey، وقارئ biometricSignInEnabled مع معيّنه، وensureDemoAccount() وfindByEmail() وcreateUser() وverifyCredentials() وsaveSession() وreadSession() وclearSession()، والدالة الثابتة hash().
Does
Accounts live as one JSON list under a single key, and the session as one JSON document. findByEmail() lower-cases both sides, so the same address cannot be registered twice by changing its case. hash() is an FNV-style digest: not cryptography, but enough that no password is ever written in clear text, and the class doc states plainly that this is a demo fallback and that a production build sets allowOfflineFirebaseFallback = false so the file is never reached. ensureDemoAccount() is idempotent, which is what makes it safe to call on every launch. Both readers catch FormatException and return empty rather than crashing the splash. The biometric opt-in is deliberately stored here and not in Firestore: it describes this handset, so an account opened on a tablet with no enrolled finger must not inherit an opt-in it can never satisfy.
يفعل
الحسابات قائمة JSON واحدة تحت مفتاح واحد، والجلسة مستند JSON واحد. تقلب findByEmail() الحروف في الطرفين فلا يُسجَّل العنوان مرتين بتغيير حالة حروفه. وhash() بصمة بأسلوب FNV: ليست تشفيرًا لكنها تكفي لألّا تُكتب كلمة المرور صريحة أبدًا، ويصرّح نصّ الفئة أنها بديل للتجربة وأن بناء الإنتاج يضبط allowOfflineFirebaseFallback = false فلا يُقرأ هذا الملف أبدًا. وensureDemoAccount() نافٍ للتكرار، وهذا ما يجعل النداء عليه في كل إقلاع آمنًا. والقارئان يلتقطان FormatException ويعيدان فراغًا بدل أن يُقتل الإقلاع. وأما الموافقة على القياس البيومتري فتحفظ هنا لا في Firestore لأنها صفة هذا الهاتف: فحساب فُتح على لوح بلا بصمة مسجّلة لا يجوز أن يرث موافقة لا يستطيع الوفاء بها.

streetbite_capstone/lib/data/datasources/auth_remote_data_source.dartdata112 lines

Firebase Authentication, with every Firebase error code translated into a StreetBite key in one table.

Firebase Authentication، مع جدول واحد يحوّل كل رمز خطأ في Firebase إلى مفتاح StreetBite.

Has
currentUser, authStateChanges(), refreshIdToken(), login(), signUp(), logout() and the static mapAuthError() switch over nine Firebase codes.
يحتوي
currentUser وauthStateChanges() وrefreshIdToken() وlogin() وsignUp() وlogout() والدالة الثابتة mapAuthError() التي تفرّع تسعة رموز من Firebase.
Does
Each method returns a UserModel built by UserModel.fromFirebase, so the widget layer never sees a Firebase class. The whole app reads Firebase errors through one table: invalid-email, email-already-in-use, weak-password, user-not-found, wrong-password, invalid-credential, too-many-requests, network-request-failed and a catch-all. Note that invalid-credential deliberately maps to the same key as wrong-password: Firebase returns it for both cases and does not say which one it is, and the app must not claim more knowledge than the backend gives. signUp() needs a second call because the sign-up payload carries no display name, and by then the account already exists. refreshIdToken() is the least obvious line in the file: after a cold start Firebase restores currentUser from disk together with an ID token that may already be expired, and Firestore attaches that stale token to its first request, which the server rejects with PERMISSION_DENIED — indistinguishable from broken security rules.
يفعل
كل دالة ترجع UserModel مبنيًا بـ UserModel.fromFirebase فلا ترى طبقة الواجهة صنفًا من Firebase أبدًا. يقرأ التطبيق كل أخطاء Firebase من جدول واحد: invalid-email وemail-already-in-use وweak-password وuser-not-found وwrong-password وinvalid-credential وtoo-many-requests وnetwork-request-failed ومدخل أخير شامل. وانتبه إلى أن invalid-credential يُترجَم عمدًا إلى مفتاح wrong-password نفسه: لأن Firebase يرجعه للحالتين ولا يقول أيهما، فلا يجوز للتطبيق أن يدّعي معرفة أكثر مما أعطى الخادم. وsignUp() تحتاج نداءً ثانيًا لأن حمولة التسجيل لا تحمل اسمًا عرض، وبينها يكون الحساب قد وُجد فعلًا. وأما refreshIdToken() فأقل سطر بديهيًا في الملف: بعد إقلاع بارد يستعيد Firebase currentUser من القرص مع رمز هوية قد يكون انتهى، ويلصقه Firestore بأول طلب فيرفضه الخادم بـ PERMISSION_DENIED — وهو ما لا يفرّقه أحد عن قواعد حماية كاسرة.

streetbite_capstone/lib/data/datasources/firestore_service.dartdata161 lines

The singleton gateway: the only file in the app that writes a Firestore path.

البوابة الوحيدة: الملف الوحيد الذي يكتب مسارًا في Firestore.

Has
FirestoreService._() with a static _instance and a factory FirestoreService(), the static _configured and _firestore fields, configure(), the isAvailable getter, the firestore getter, three collection accessors, and six operations: readDocument(), upsertDocument(), readCollection(), readSubCollection(), writeToSubCollection(), deleteFromSubCollection().
يحتوي
FirestoreService._() مع _instance ثابت وfactory FirestoreService()، والحقلين الثابتين _configured و_firestore، وconfigure() وقارئ isAvailable وقارئ firestore، وثلاثة ملتقطات مجموعات، وست عمليات: readDocument() وupsertDocument() وreadCollection() وreadSubCollection() وwriteToSubCollection() وdeleteFromSubCollection().
Does
The singleton is enforced by the compiler, not by convention: the private constructor makes external instantiation impossible. configure(null) is the offline-fallback switch — the service then reports isAvailable == false and every repository transparently serves its local branch instead of failing. The firestore getter throws FirestoreNotAvailableException rather than returning null: a missing configuration must be loud during development, and it is safe to be loud because the repository layer catches it and turns it into a friendly message. Every write uses SetOptions(merge: true), so a one-field patch such as a new photoUrl cannot erase the rest of a profile document.
يفعل
نمط النسخة الوحيدة يفرضه المُصرِّف لا العُرف: الباني الخاص يستحيل معه الإنشاء من خارج الملف. وconfigure(null) هو مفتاح البديل المحلي؛ عندئذ تُعلن البوابة isAvailable == false فيخدم كل مستودع فرعَه المحلي بصمت بدل أن يفشل. وقارئ firestore يرمي FirestoreNotAvailableException ولا يرجع null: غياب الإعداد يجب أن يكون صاخبًا في التطوير، والصخب آمن لأن المستودع يلتقطه ويحوّله رسالة لطيفة. وكل كتابة تستخدم SetOptions(merge: true) فلا يستطيع تحديث حقل واحد مثل photoUrl أن يمحو بقية ملف المستخدم.
Needs
The cloud_firestore package and core/error/exceptions.dart; it is handed its instance by injection.dart, never by a screen.
يحتاج
حزمة cloud_firestore وcore/error/exceptions.dart؛ وتسلم نسختها من injection.dart لا من أي شاشة.

streetbite_capstone/lib/data/services/biometric_service.dartdata143 lines

The wall between local_auth and the UI: six outcomes, no platform codes.

السور بين local_auth والواجهة: ست نتائج ولا رموز منصة.

Has
BiometricService({LocalAuthentication? auth}) with isAvailable(), authenticate({required reason}) and the private _classify(); plus BiometricResult carrying isSuccess and messageKey with the named constructors success, failure(), cancelled(), unavailable(), notEnrolled() and lockedOut().
يحتوي
BiometricService({LocalAuthentication? auth}) فيه isAvailable() وauthenticate({required reason}) والدالة الخاصة _classify()؛ وصنف BiometricResult يحمل isSuccess وmessageKey وله دوال بناء مسماة هي success وfailure() وcancelled() وunavailable() وnotEnrolled() وlockedOut().
Does
isAvailable() asks three questions instead of one, and the third is the one people forget: canCheckBiometrics answers "is this device capable?", which stays true on a handset whose owner never enrolled a finger — offering that user a prompt is offering them a failure. authenticate() therefore checks support, capability and enrolment separately and returns notEnrolled() when only the last fails, because the remedy differs: one cannot be fixed by retrying, the other needs Settings. _classify() matches on LocalAuthExceptionCode rather than substring-matching error.toString() the way the previous implementation did, which is what stops a renamed platform code from silently degrading to a generic "try again". The switch keeps a default branch on purpose: the plugin documents that new codes may arrive without a major version bump. The constructor takes an optional LocalAuthentication so a test can inject a fake.
يفعل
تسأل isAvailable() ثلاثة أسئلة لا سؤالًا، والثالث هو المنسي: canCheckBiometrics تجيب «هل هذا الجهاز قادر?» وتظل صحيحة في هاتف لم يسجّل صاحبه بصمة أصلًا — فأن تعرض لذلك المستخدم طلبًا هو أن تعرض له فشلًا. لذا تفحص authenticate() الدعم والقدرة والتسجيل منفصلة وترجع notEnrolled() إن كان الفشل في الأخير وحده، لأن العلاج يختلف: هذا لا يصلحه إعادة المحاولة وذاك يحتاج الإعدادات. و_classify() تفرّع على LocalAuthExceptionCode لا على error.toString() كما كان السابق يفعل، وهذا ما يمنع رمز منصة مُعاد تسميته أن ينحدر بصمت إلى «حاول مجددًا» عامة. ويبقي الفرع على default عمدًا لأن الحزمة توثق أن رموزًا جديدة قد تأتي بلا تغيير إصدار رئيسي. ويأخذ الباني LocalAuthentication اختياريًا حتى يتمكن الاختبار من حقن نسخة وهمية.

How this document was made. Written against commit 07b200f. Every card was produced by reading the file it describes; the line counts, declaration names and import lists are extracted from the source tree by _audit/imports.py, and _audit/build_guide.py refuses to build if a card points at a Dart file that no longer exists. Nothing here is remembered from a previous draft.

Companion documents. docs/code-doc/index.html explains the concepts (architecture, state, errors, security) layer by layer; this guide answers the other question — what is each file for. docs/StreetBite_Capstone_Report_EN-AR.pptx is the slide deck for the defence itself.

Language. Both columns are on by default; the sidebar switches to English or Arabic only. Paths, identifiers and code are never translated, because Either<Failure, List<MealEntity>> reads the same in either language.

كيف صُنعت هذه الوثيقة. كُتبت عند الالتزام 07b200f. وكل بطاقة نُقلت بعد قراءة الملف الموصوف؛ وأعداد الأسطر وأسماء التصريحات وقوائم الاستيراد تُستخرج من شجرة المصدر بواسطة _audit/imports.py، و_audit/build_guide.py يرفض البناء إذا أشارت بطاقة إلى ملف Dart لم يعد موجودًا. ولا شيء هنا من الاستذكار.

الوثائق المكمّلة. يشرح docs/code-doc/index.html المفاهيم (المعمارية، الحالة، الأخطاء، الحماية) طبقة طبقة؛ أما هذا الدليل فيجيب عن السؤال الآخر: ما وظيفة كل ملف. وملف docs/StreetBite_Capstone_Report_EN-AR.pptx هو العرض التقديمي للمناقشة.

اللغة. العمودان ظاهران افتراضيًا، ويحوّلهما الشريط الجانبي إلى الإنجليزية أو العربية وحدها. ولا تُترجَم المسارات والمعرّفات والشفرة أبدًا، لأن Either<Failure, List<MealEntity>> تُقرأ بالشكل نفسه في اللغتين.
