12 ‏lib/domain/entities — eight pure-Dart files that decide what a thing *is*‏lib/domain/entities — ثمانية ملفات Dart خالصة تقرّر معنى «الشيء»

Eight files, no Flutter import, no JSON, no async. These are the types the business talks about: a dish, an account, an order, a payment strategy, a cart line, a saved meal, a vendor, the handset itself. Five of them are records; three of them carry real behaviour — an order that knows when it stopped being active, a cart line that knows its own total, and a payment strategy that knows how to print itself on a receipt.

Seven of the eight extend Equatable. That single choice is what lets a Bloc compare two states by value, so the props list in each file is not bookkeeping — it is the equality contract the UI is built on.

ثمانية ملفات، بلا استيراد Flutter ولا JSON ولا async. هذه هي الأنواع التي يتحدّث عنها العمل: صحن، وحساب، وطلب، واستراتيجية دفع، وسطر سلة، وصحن محفوظ، وبائع، والهاتف نفسه. خمسة منها سجلّات، وثلاثة تحمل سلوكًا حقيقيًا: طلب يعرف متى خرج من حالة النشاط، وسطر سلة يعرف إجماليه، واستراتيجية دفع تعرف كيف تُطبع في إيصال.

سبعة من الثمانية تمتد Equatable. هذا الخيار وحده ما يسمح لأي Bloc بأن يقارن حالتين بالقيمة، فليست قائمة props في كل ملف حشوًا — بل هي عقد المساواة الذي تُبنى عليه الواجهة.

streetbite_capstone/lib/domain/entities/meal_entity.dartdomain50 lines

The dish as the app thinks about it: nine fields, one equality rule, no serialisation.

الصحن كما يفكّر فيه التطبيق: تسعة حقول، وقاعدة مساواة واحدة، ولا تسلسل.

Has
id, name, category, area, instructions, thumbnailUrl, price, tags and the nullable youtubeUrl, plus the overridden props.
يحتوي
id وname وcategory وarea وinstructions وthumbnailUrl وprice وtags وyoutubeUrl القابل للعدم، مع props المتجاوزة.
Does
Extending Equatable is what lets two meals built from different sources compare by value, so the cart and the favourites can ask 'is this the same dish' without an id dance in every widget. Look at what props leaves out: youtubeUrl is a field but not a property, so two meals differing only in their video link are equal — harmless for the feed, because nothing re-renders on that value, and worth stating out loud in a defence when asked how equality was designed. The doc comment carries the architectural rule of the whole layer — the entity owns behaviour and the model owns serialisation — and records why the price lives here at all: TheMealDB publishes none, so the data layer derives it and the entity documents the derivation instead of hiding it.
يفعل
مدّ Equatable هو ما يجعل صحنين مبنيين من مصدرين متمايزين يتساويان بالقيمة، فتستطيع السلة والمفضلة أن تسألا «أهو الصحن نفسه» بلا مواربة المعرّف في كل صنف واجهة. وانظر إلى ما تُسقطه props: فـ youtubeUrl حقل ليس خاصية، فيصير صحنان يختلفان في رابط الفيديو فقط متساويين — وهذا لا ضرر فيه على الموجة لأن لا شيء يُعاد رسمه وفق تلك القيمة، وذكره في المناقشة أصدق من تركه سؤالًا محرجًا. ويحمل تعليق الصنف قاعدة الطبقة كلها: الكيان يملك السلوك والنموذج يملك التسلسل — ويوثّق لماذا يقيم الثمن هنا أصلًا: لأن TheMealDB لا ينشر أسعارًا، فتشتقه طبقة البيانات منه، ويكتفي الكيان بتوثيق الاشتقاق لا بإخفائه.

streetbite_capstone/lib/domain/entities/user_entity.dartdomain40 lines

The account as five values — and a signature that refuses to let identity change.

الحساب خمس قيم — وتوقيع لا يسمح للهوية بأن تتغيّر.

Has
uid, email, displayName, the nullable photoUrl, the nullable createdAt, copyWith() and props.
يحتوي
uid وemail وdisplayName وphotoUrl القابل للعدم وcreatedAt القابل للعدم، مع copyWith() وprops.
Does
copyWith() accepts only displayName and photoUrl: the uid and the e-mail cannot be edited, a claim the type system enforces for you, so no screen can invent a parameter that would rewrite an account's identity. photoUrl is nullable because the local fallback store has no picture to offer, and createdAt likewise because a session restored from disk may never have written one. The class doc explains why the data layer builds this entity through a Builder; note honestly that the same comment still mentions a bio field the class does not declare — a stale line left from a sign-up flow that dropped the field, and exactly the kind of drift a reviewer reads first.
يفعل
لا تقبل copyWith() إلا displayName وphotoUrl: فالمعرّف والبريد لا يُحرّران، ودعوى يفرضها نظام الأنواع نيابة عنك فلا تستطيع شاشة أن تخترع وسيطًا يعيد كتابة هوية حساب. وphotoUrl قابل للعدم لأن المخزن المحلي البديل ليس لديه صورة يعطيها، ومثله createdAt لأن جلسة مستعادة من القرص قد لا تكون كتبته يومًا. يشرح تعليق الصنف لماذا تبنيه طبقة البيانات ببانٍ؛ واذكر بصدق أن نفس التعليق ما زال يذكر حقل bio لا وجود له في الصنف — سطر باقٍ من تدفق تسجيل تخلّى عن الحقل، وهو من نوع الفروق التي يقرأها المراجع أول ما يقرأ.

streetbite_capstone/lib/domain/entities/order_entity.dartdomain100 lines

Behaviour where behaviour is expensive: an order decides, on read, whether it is still live.

سلوك حيث يكلُف السلوك: الطلب يقرر، عند القراءة، هل ما زال حيًا.

Has
Ten fields, the derived total and itemCount getters, statusAt(now), copyWith(), props, and enum OrderStatus {active, past} with a stored key and a static fromKey().
يحتوي
عشرة حقول، ومُعرِّفا total وitemCount المشتقان، وstatusAt(now)، وcopyWith()، وprops، وenum OrderStatus {active, past} بمخزَّن key ودالة ثابتة fromKey().
Does
The status in the document records what was true at checkout; it is a snapshot, not a live claim. statusAt() resolves it against AppConstants.orderActiveWindow (forty-five minutes), and the doc comment spells out why the new value is never written back: no client can mark an order delivered for a kitchen it cannot see, but every reader can still be given the honest answer. fromKey() falls back to past rather than throwing, so an unknown status string ages an order out instead of crashing the tab. itemCount folds the quantities, which is the difference between 'three lines' and 'six servings' on the receipt.
يفعل
تسجل status في الوثيقة ما كان صحيحًا عند الدفع؛ إنها لقطة لا دعوى حيّة. تحلّ statusAt() اللقطة مقابل AppConstants.orderActiveWindow (خمس وأربعون دقيقة)، ويكتب التعليق السبب في عدم إرجاع القيمة الجديدة: لا يستطيع عميل أن يوسم طلبًا بالتسليم لمطبخ لا يراه، لكن يحق لكل قارئ أن يُعطى الجواب الصادق. وترجع fromKey() إلى past بدل أن ترمي، فسلسلة حالة مجهولة تُقادم الطلب لا تُسقط التبويب. وتجمع itemCount الكميات، وهذا هو الفرق بين «ثلاثة أسطر» و«ست حصص» في الإيصال.

streetbite_capstone/lib/domain/entities/payment.dartdomain109 lines

The SOLID exhibit of the project: one narrow interface, two strategies, one persisted enum.

معرض SOLID في المشروع: واجهة ضيّقة واحدة، واستراتيجيتان، وتعداد مخزَّن.

Has
enum PaymentType {cash, card} with key and fromKey(); abstract interface class PaymentMethod with type, labelKey, descriptionKey, receiptLine() and its own == and hashCode; CashPayment; and CardPayment({last4 = '4242'}).
يحتوي
enum PaymentType {cash, card} مع key وfromKey()؛ وabstract interface class PaymentMethod وفيها type وlabelKey وdescriptionKey وreceiptLine() مع == وhashCode خاصين بها؛ وCashPayment؛ وCardPayment({last4 = '4242'}).
Does
This is the Strategy pattern with the doc comment to prove it: the five SOLID points are named one by one in the file header, and the code really does match — adding a wallet means adding a class, never editing checkout. The interface stays language-free by carrying ARB keys and taking the already-localised word into receiptLine(), so the domain never knows Arabic exists and the widget never builds a money sentence by hand. Unlike every other entity this one does not extend Equatable: it writes == itself, comparing by type at the interface level and additionally by last4 inside CardPayment. fromKey() defaults to cash, so a stored value the app does not recognise pays on delivery rather than throwing at checkout. last4 is the only card data that can exist here at all.
يفعل
هذا نمط الاستراتيجية مع دليل مكتوب: نقاط SOLID الخمس مسمّاة واحدًا واحدًا في رأس الملف، والشيفرة تطابقها فعلًا — فإضافة محفظة تعني صنفًا جديدًا لا تحرير شاشة الدفع. وتبقى الواجهة نظيفة من اللغة بأنها تحمل مفاتيح ARB وتأخذ الكلمة المترجمة سلفًا إلى receiptLine()، فلا يعرف النطاق أن العربية موجودة ولا تكتب الواجهة جملة مال بيدها. وخلافًا لكل الكيانات الأخرى، لا يمتد هذا الصنف Equatable: بل يكتب == بنفسه، فيقارن بـ type على مستوى الواجهة ويزيد last4 داخل CardPayment. وfromKey() ترجع إلى النقد دائمًا، فقيمة مخزّنة لا يعرفها التطبيق تُدفع عند التسليم بدل أن ترمي عند الدفع. وليس بوسط هنا أن يوجد من بطاقة سوى آخر أربعة أرقام.
Needs
none — pure Dart, no imports
يحتاج
لا شيء — Dart خالصة بلا أي استيراد

streetbite_capstone/lib/domain/entities/cart_item_entity.dartdomain20 lines

One cart line, and the only place a line total is computed.

سطر سلة واحد، والموضع الوحيد الذي يُحسب فيه إجمالي السطر.

Has
meal, quantity, the derived lineTotal, copyWith() and props.
يحتوي
meal وquantity وlineTotal المشتق وcopyWith() وprops.
Does
lineTotal multiplies the entity's price by the quantity, and that single getter is what CalculateOrderTotals folds — so the cart, the checkout screen, the Firestore document and the unit tests all read the same formula, which is the cheapest possible defence against a total that disagrees with its own lines. copyWith() exists because the cart is immutable: AddToCart and RemoveFromCart return a new list instead of mutating one, and that is what makes a Bloc state diff meaningful. streetbite_capstone/lib/domain/entities/device_info_entity.dartdomain33 lines

Four strings that let the Profile screen render without ever importing a plugin.

أربعة نصوص تسمح لشاشة الملف الشخصي بأن تُرسم بلا استيراد أي ملحق.

Has
model, osVersion, deviceName, manufacturer, props and the static DeviceInfoEntity.unknown.
يحتوي
model وosVersion وdeviceName وmanufacturer وprops والثابت DeviceInfoEntity.unknown.
Does
This is a null object in the textbook sense: unknown is a fully populated instance whose four values read Unknown, so the only failure path in GetDeviceInfo still returns a Right with something renderable. That choice is why the Profile cubit holds a device field that is never nullable and never has a 'loading failed' branch — the state is always displayable. It also keeps device_info_plus behind a use case, so no widget file in the project imports a platform plugin.
يفعل
هذا الكائن الفارغ بمعنى الكتاب: فـ unknown نسخة مكتملة القيم الأربعة كلها Unknown، فيبقى مسار الفشل الوحيد في GetDeviceInfo يرجع Right بشيء قابل للعرض. وهذا الاختيار هو سبب امتلاك Cubit الملف الشخصي حقل device غير قابل للعدم ولا فرع فيه لـ «فشل التحميل» — فالحالة قابلة للعرض دائمًا. وهو أيضًا ما يبقي device_info_plus وراء حالة استخدام، فلا يستورد أي ملف واجهة ملحق منصة في المشروع.

How this document was made. Written against commit 07b200f. Every card was produced by reading the file it describes; the line counts, declaration names and import lists are extracted from the source tree by _audit/imports.py, and _audit/build_guide.py refuses to build if a card points at a Dart file that no longer exists. Nothing here is remembered from a previous draft.

Companion documents. docs/code-doc/index.html explains the concepts (architecture, state, errors, security) layer by layer; this guide answers the other question — what is each file for. docs/StreetBite_Capstone_Report_EN-AR.pptx is the slide deck for the defence itself.

Language. Both columns are on by default; the sidebar switches to English or Arabic only. Paths, identifiers and code are never translated, because Either<Failure, List<MealEntity>> reads the same in either language.

الوثائق المكمّلة. يشرح docs/code-doc/index.html المفاهيم (المعمارية، الحالة، الأخطاء، الحماية) طبقة طبقة؛ أما هذا الدليل فيجيب عن السؤال الآخر: ما وظيفة كل ملف. وملف docs/StreetBite_Capstone_Report_EN-AR.pptx هو العرض التقديمي للمناقشة.

اللغة. العمودان ظاهران افتراضيًا، ويحوّلهما الشريط الجانبي إلى الإنجليزية أو العربية وحدها. ولا تُترجَم المسارات والمعرّفات والشفرة أبدًا، لأن Either<Failure, List<MealEntity>> تُقرأ بالشكل نفسه في اللغتين.
