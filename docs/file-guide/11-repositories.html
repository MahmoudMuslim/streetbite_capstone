11 ‏lib/data/repositories — the policy layer: what to try, in what order, and what to answer when it fails‏lib/data/repositories — طبقة السياسة: ماذا تجرّب، وبأي ترتيب، وما الجواب حين يفشل

Six files, one per interface in lib/domain/repositories. They are the only place in the app where a decision such as "retry offline", "serve the cache", "report success anyway" is made. The data sources above them know how to talk to one system; the widgets below them know nothing about any system. Everything between those two boundaries is policy, and policy lives here.

Two rules repeat in every card: a repository never throws — each failure path ends in a Failure inside a Left — and each one answers something when the backend is absent, so a demo device without Play Services still walks the user through the whole flow.

ستة ملفات، واحد لكل واجهة في lib/domain/repositories. وهي المواضع الوحيدة في التطبيق التي تُتَّخذ فيها قرارات مثل «أعِد المحاولة بلا شبكة» و«اخدم من المخزون» و«أعلن النجاح رغم الغياب». مصادر البيانات فوقها تعرف كيف تخاطب نظامًا واحدًا؛ وأصناف الواجهة تحتها لا تعرف عن الأنظمة شيئًا. وما بين الحدَّين سياسة، والسياسة تسكن هنا.

قاعدتان تتكرران في كل بطاقة: المستودع لا يرمي استثناءً أبدًا — كل مسار فشل ينتهي بـ Failure داخل Left — وكل مستودع يجيب بشيء حين يكون الخادم غائبًا، فيظل جهاز بلا خدمات Google يُنجز الرحلة كاملة.

streetbite_capstone/lib/data/repositories/auth_repository_impl.dartdata183 lines

The only place where the Firebase-versus-local decision is made, and the file that turns a backend outage into a working app instead of a dead-end error screen.

الموضع الوحيد الذي يُتَّخذ فيه قرار Firebase أو المخزن المحلي، والملف الذي يحوّل انقطاع الخادم إلى تطبيق يعمل بدل شاشة خطأ مسدودة.

Has
_remote (nullable) and _local (required), the _firebaseUsable getter, restoreSession(), _refreshToken(), login(), signUp(), logout(), biometricSignInEnabled, setBiometricSignInEnabled() and authStateChanges(), plus the private _loginLocally() and the _isConnectivityFailure() predicate.
يحتوي
_remote التي قد تكون معدومة و_local الإلزامية، والمُعرِّف _firebaseUsable، وrestoreSession() و_refreshToken() وlogin() وsignUp() وlogout() وbiometricSignInEnabled وsetBiometricSignInEnabled() وauthStateChanges()، والدالة الخاصة _loginLocally() والحارس _isConnectivityFailure().
Does
Implements the three-step resilience rule written in its own class doc: try Firebase, surface a credential error verbatim, and retry against the local store only for a connectivity-shaped failure. _isConnectivityFailure() is the whole safety interlock — it accepts only authErrorNetwork and authErrorUnknown, so a wrong password can never be quietly answered by the fallback store, and the Appium suite cannot produce a false pass on a machine that has no network. restoreSession() refuses to fall back at all while Firebase is configured, and the comment states why: the zombie session, a signed-in Home screen whose every Firestore read came back PERMISSION_DENIED. _refreshToken() exists for the same bug and swallows its own failures so an offline device still opens the app. logout() clears both halves, since leaving the local session behind would resurrect the user at the next cold start. The biometric pair is a pure pass-through to the local store because the opt-in describes the handset, not the account. One wrinkle is worth admitting in a defence rather than hiding: _firebaseUsable is _remote != null && AppConstants.allowOfflineFirebaseFallback, so that constant really gates whether Firebase is consulted at all, while the local data source doc advises setting it to false in production — the two comments describe opposite builds.
يفعل
ينفّذ خطوات الصمود الثلاث المكتوبة في تعليق صنفه: جرّب Firebase، وأظهر خطأ بيانات الاعتماد كما هو، وأعد المحاولة على المخزن المحلي عند فشل الشبه بالشبكة فقط. والحارس _isConnectivityFailure() هو قفل الأمان كله: لا يقبل إلا authErrorNetwork وauthErrorUnknown، فلا تُجاب كلمة مرور خاطئة بصمت من المخزن البديل، ولا تُنتج حزمة Appium نجاحًا زائفًا على جهاز بلا شبكة. وترفض restoreSession() أي تراجع ما دام Firebase مضبوطًا، ويشرح التعليق السبب: جلسة الزومبي التي تُظهر الرئيسية مسجَّلة بينما كل قراءة Firestore ترجع PERMISSION_DENIED. و_refreshToken() موجودة للغلط نفسه وتبتلع فشلها ليظل الجهاز المنقطع يفتح التطبيق. ويمحو logout() النصفين معًا لأن إبقاء الجلسة المحلية يُعيد إحياء المستخدم عند الإقلاع التالي. وثنائي القياس البيومتري تمرير صافٍ إلى المخزن المحلي لأن الموافقة صفة الهاتف لا الحساب. وثغرة تُذكر في المناقشة لا تُخفى: _firebaseUsable هو _remote != null && AppConstants.allowOfflineFirebaseFallback، فذلك الثابت يقرر في الحقيقة ما إذا كان Firebase يُستشار أصلًا، بينما ينصح تعليق مصدر البيانات المحلي بضبطه على false في الإنتاج — أي أن التعليقين يصفان بناءً متعاكسًا.

streetbite_capstone/lib/data/repositories/favourite_repository_impl.dartdata88 lines

Hearted meals scoped to one user, with the toggle that Firestore does not provide.

قلوب محفوظة لمستخدم واحد، مع التبديل الذي لا يوفره Firestore.

Has
_firestore, toggleFavourite({uid, meal}) and getFavourites(uid).
يحتوي
_firestore وtoggleFavourite({uid, meal}) وgetFavourites(uid).
Does
Read-then-write: one readDocument() decides whether the document exists, and the branch then either deletes it or writes FavouriteModel(...).toJson() through writeToSubCollection(). The read is not waste — Firestore has no toggle primitive, the same read would be needed server-side anyway, and its answer is exactly what tells the caller which SnackBar key to show. When Firestore is unconfigured the file answers Right(true) for the toggle and Right([]) for the list: nothing is persisted, but the interface keeps a coherent state instead of flashing an error the user can do nothing about. Every FirebaseException becomes a ServerFailure that keeps the server text in details. Sorting by savedAt descending happens here, so 'most recently hearted first' is repository policy rather than widget code — which is why the same order appears if the list is ever rendered elsewhere.
يفعل
قراءة ثم كتابة: readDocument() واحدة تقرر إن كان المستند موجودًا، ثم يحذفه الفرع المناسب أو يكتب FavouriteModel(...).toJson() عبر writeToSubCollection(). والقراءة ليست هدرًا — لا primitive للتبديل في Firestore، ونفس القراءة كانت ستلزم في الخادم أيضًا، وجوابها هو بالضبط ما يخبر المستدعي أي مفتاح SnackBar يُعرض. وحين يكون Firestore غير مضبوط تُجاب البديل بـ Right(true) والقائمة بـ Right([]): لا شيء يُخزَّن، لكن الواجهة تبقى في حالة متماسكة بدل وميض خطأ لا حيلة للمستخدم فيه. ويتحول كل FirebaseException إلى ServerFailure يحفظ نص الخادم في details. والترتيب حسب savedAt تنازليًا يجري هنا، فتكون «الأحدث قلبًا أولًا» سياسة المستودع لا شيفرة الشاشة — ولهذا يظهر الترتيب نفسه في أي مكان آخر تُعرض فيه القائمة.

streetbite_capstone/lib/data/repositories/meal_repository_impl.dartdata137 lines

The Factory pattern the brief asked for, written as one enum and one method.

نمط المصنع الذي طلبه التكليف، مكتوبًا في تعداد واحد ودالة واحدة.

Has
enum MealDataSource {remote, local, remoteThenLocal}, the defaultSource constant, getMeals(), getHotOffers(), selectDataSource(), _fetch(), _loadRemote(), _readCache() and _persist().
يحتوي
enum MealDataSource {remote, local, remoteThenLocal}، والثابت defaultSource، وgetMeals() وgetHotOffers() وselectDataSource() و_fetch() و_loadRemote() و_readCache() و_persist().
Does
selectDataSource() is the single home of the mapping from intent to source, so no call site carries a switch and a third backend would cost one enum value plus one branch here. _fetch() then runs the chosen strategy: the remote branches write the cache after a success, remoteThenLocal degrades to the cache on NetworkException and reports ServerFailure only when the cache is empty as well, and local never touches the network — answering CacheFailure when nothing has been cached yet. _readCache() converts a corrupt payload's SerializationException into an empty list so the caller can decide, and remoteThenLocal turns it into CacheFailure: the Cubit receives a Failure, never an exception, which is the app-wide no-unhandled-exceptions rule enforced at this boundary. The switch has no default on purpose — the compiler checks that every strategy is handled, and that check is the reason the enum is declared in this file rather than in the domain.
يفعل
selectDataSource() البيت الوحيد للخريطة من النية إلى المصدر، فلا يحمل موضع نداء switch ولا تكلفة لخادم ثالث سوى قيمة في التعداد وفرع هنا. ثم ينفذ _fetch() الاستراتيجية المختارة: فروع الشبكة تكتب المخزون بعد النجاح، وremoteThenLocal يتدهور إلى المخزون عند NetworkException ولا يعلن ServerFailure إلا إذا كان المخزون فارغًا هو أيضًا، وlocal لا يلمس الشبكة أبدًا فيجيب CacheFailure حين لا شيء مخزَّن بعد. وتحول _readCache() تفسّخ الحمولة إلى قائمة فارغة ليقرر المستدعي، ويحوّلها remoteThenLocal إلى CacheFailure: فيصل Cubit فشلٌ لا استثناء، وهذا هو سريان قاعدة عدم رمي استثناءات بلا معالجة على هذا الحد. ويبقى switch بلا default عمدًا — المُصرِّف يتأكد أن كل استراتيجية معالجة، وهذا الفحص هو سبب إعلان التعداد في هذا الملف لا في النطاق.

streetbite_capstone/lib/data/repositories/vendor_repository_impl.dartdata26 lines

Twenty-six lines whose job is to keep a map screen honest about where its data comes from.

ستة وعشرون سطرًا وظيفتها أن تبقى شاشة الخريطة صادقة حول مصدر بياناتها.

Has
_local and one method, getNearbyVendors().
يحتوي
_local ودالة واحدة، getNearbyVendors().
Does
It hands the call to VendorLocalDataSource.getVendorEntities(), which performs the model-to-entity widening at the edge of the layer, and wraps everything in a try/catch that turns any error into CacheFailure — a formality today, since a const list cannot fail, but the exact shape the method must already have when the same call becomes a Firestore geo-query. This is also the smallest honest example of the repository rule: no business decision, just typing and error translation.
يفعل

How this document was made. Written against commit 07b200f. Every card was produced by reading the file it describes; the line counts, declaration names and import lists are extracted from the source tree by _audit/imports.py, and _audit/build_guide.py refuses to build if a card points at a Dart file that no longer exists. Nothing here is remembered from a previous draft.

Companion documents. docs/code-doc/index.html explains the concepts (architecture, state, errors, security) layer by layer; this guide answers the other question — what is each file for. docs/StreetBite_Capstone_Report_EN-AR.pptx is the slide deck for the defence itself.

Language. Both columns are on by default; the sidebar switches to English or Arabic only. Paths, identifiers and code are never translated, because Either<Failure, List<MealEntity>> reads the same in either language.
