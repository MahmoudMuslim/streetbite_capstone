01 The repository root — seven folders, one productجذر المستودع — سبعة مجلدات ومنتج واحد

The graduation submission is a monorepo: the app, its end-to-end test suite, its manual-QA evidence, its documentation, its design reference and its build tooling all live in one Git repository so that an examiner can clone one URL and get everything. Six of the seven folders are tracked in Git; _audit/ and .idea/ are deliberately ignored.

  • Ship the product → streetbite_capstone/
  • Prove it works → automation/ + manual_qa/
  • Explain it → docs/ (this guide lives here too)
  • Redraw it → figma/ (the design it was built against)
  • Regenerate the docs → _audit/ (local-only tooling)

تسليم التخرّج هو مستودع واحد (monorepo): التطبيق وحزمة اختبارات النهاية إلى النهاية ودليل الاختبار اليدوي والوثائق ومرجع التصميم وأدوات البناء كلها في مستودع Git واحد، فيستنسخ المناقش رابطًا واحدًا ويجد كل شيء. ستة من السبعة مجلدات متتبَّعة في Git، أما _audit/ و.idea/ فمُستثنَيتان بقصد.

  • منتج يُشغَّل ← streetbite_capstone/
  • إثبات أنه يعمل ← automation/ وmanual_qa/
  • شرح ما فُعِل ← docs/ (وهذا الدليل يسكن هنا أيضًا)
  • مرجع الرسم ← figma/ (التصميم الذي بُني عليه التطبيق)
  • إعادة توليد الوثائق ← _audit/ (أدوات محلية لا تُرفَع)
README.mddoc

The one-page map of the whole submission — the first thing a marker reads.

الخريطة من صفحة واحدة لكامل التسليم — أول ما يقرأه المقيّم.

Has
A tree diagram of the six folders, a four-step quick start (flutter pub get → flutter run → flutter test → mvn test), a "What's inside" table per folder, and the resilience claim ("runs with no Firebase configuration").
يحتوي
رسم شجرة المجلدات الستة، وأربع خطوات للتشغيل السريع (flutter pub get ثم flutter run ثم flutter test ثم mvn test)، وجدول «ما في كل مجلد»، وعبارة المرونة («يعمل دون أي إعداد Firebase»).
Does
Sets the reader's mental model before they open any file, and states the measurable results: 0 analyzer issues, 95 unit/widget tests, 6/6 Appium tests green, 51 manual cases.
يفعل
يبني النموذج الذهني للقارئ قبل فتح أي ملف، ويذكر النتائج القابلة للقياس: صفر ملاحظات في المحلّل، و٩٥ اختبارًا، و٦/٦ في Appium، و٥١ حالة اختبار يدوي.
Needs
Nothing at run time — it is documentation. Its claims must stay true, which is why every number in it is reproducible with the commands it prints.
يحتاج
لا شيء وقت التشغيل؛ توثيقٌ صرف. لذا يجب أن تبقى أرقامه صحيحة لأنها كلها قابلة لإعادة الإنتاج بأوامره المطبوعة.
Try it
Run the four commands in the Quick start block. If one of them stops working, the README is a bug report waiting to be written — fix the README or fix the project.
جرّب
نفّذ الأوامر الأربعة في «التشغيل السريع». إن توقّف أحدها فذلك خطأ في README نفسه: أصلح الأمر أو أصلح الوثيقة.
.gitignorecfg

Keeps build output, IDE state and secrets out of Git.

يبقى مخرجات البناء وحالة المحرّر والأسرار خارج Git.

Has
Rules for _audit/, .idea/, Thumbs.db, .DS_Store, plus a comment explaining why the IDE folder is ignored.
يحتوي
قواعد تستثني _audit/ و.idea/ وThumbs.db و.DS_Store، مع تعليق يشرح سبب استثناء مجلد المحرّر.
Does
Blocks the churn: Android Studio rewrites .idea/workspace.xml on every open, and the _audit/ scratch holds device screenshots and uiautomator dumps that are evidence, not source. Without these rules git status would be unreadable.
يفعل
يوقف الضجيج: فـ Android Studio يعيد كتابة .idea/workspace.xml عند كل فتح، ومجلد _audit/ فيه لقطات جهاز وتفرغات uiautomator هي أدلّة لا مصادر. وبدا هذه القواعد يصبح git status غير قابل للقراءة.
Needs
Git only. The companion file streetbite_capstone/.gitignore carries the heavier rules (build/, .dart_tool/, android/key.properties, google-services.json).
يحتاج
Git وحده. والملف المرافق streetbite_capstone/.gitignore يحمل القواعد الأثقل (build/ و.dart_tool/ وandroid/key.properties وgoogle-services.json).
Try it
Type git status --ignored and count how many ignored entries exist. That list is the boundary between «source» and «artefact» in this project.
جرّب
اكتب git status --ignored وعدّ الإدخالات المستثناة؛ تلك القائمة هي الحدّ الفاصل بين «المصدر» و«النتاج» في هذا المشروع.
streetbite_capstone/folder

The product itself: a Flutter 3.47 app with Clean Architecture and 161 hand-written Dart files.

المنتج ذاته: تطبيق بـ Flutter 3.47 بمعمارية نظيفة و١٦١ ملف Dart مكتوبًا يدويًا.

Has
lib/ (app code), test/ (95 unit + widget tests), android/ and ios/ (native shells), assets/, scripts/, and the project files pubspec.yaml, analysis_options.yaml, l10n.yaml, firestore.rules, firebase.json.
يحتوي
lib/ (شفرة التطبيق) وtest/ (٩٥ اختبار وحدة ومعيار) وandroid/ وios/ (الغلافان الأصليون) وassets/ وscripts/ وملفات المشروع pubspec.yaml وanalysis_options.yaml وl10n.yaml وfirestore.rules وfirebase.json.
Does
Everything the user touches. Its dependency rule is one-directional: presentation → domain ← data, and domain imports no Flutter class.
يفعل
كل ما يلمسه المستخدم. وقاعدة التبعية فيه أحادية الاتجاه: presentation → domain ← data، ولا يستورد domain أي صنف من Flutter.
Needs
Flutter SDK (^3.13 Dart), the 20 packages pinned in pubspec.yaml, and a Google Maps key in android/key.properties for the map screen.
يحتاج
حزمة Flutter SDK (‏^3.13 لـ Dart)، والعشرون حزمة المقيّدة في pubspec.yaml، ومفتاح Google Maps في android/key.properties لأجل شاشة الخريطة.
Try it
Read it in this order: lib/main.dart → lib/injection.dart → lib/app.dart → any screen. Sections 06–18 of this guide walk each one.
جرّب
اقرأه بهذا الترتيب: lib/main.dart ثم lib/injection.dart ثم lib/app.dart ثم أي شاشة. الأقسام ٠٦–١٨ من هذا الدليل تمشي فيها واحدًا واحدًا.
automation/folder

Appium 2 end-to-end suite in Java: 6 tests that drive the real APK on a device.

حزمة اختبارات النهاية إلى النهاية بـ Appium 2 بلغة Java: ستة اختبارات تقود ملف APK حقيقيًا على جهاز.

Has
Maven project (pom.xml, testng.xml), src/test/java/ with base/, config/, pages/, tests/, utils/, plus src/test/resources/automation.properties and a 221-line README.
يحتوي
مشروع Maven (pom.xml وtestng.xml) وsrc/test/java/ فيه base/ وconfig/ وpages/ وtests/ وutils/، مع src/test/resources/automation.properties وREADME من ٢٢١ سطرًا.
Does
Proves the app works through the Android accessibility tree the way a user does — no Flutter test hooks, no source access. Page Objects keep locators in one place.
يفعل
يُثبت أن التطبيق يعمل عبر شجرة إمكانية الوصول في Android كما يفعل المستخدم — بلا خطافات اختبار Flutter ولا وصول إلى المصدر. وكائنات الصف تحصر المحدِّدات في مكان واحد.
Needs
JDK 17, Maven, a running Appium server on 127.0.0.1:4723, an emulator or handset, and the release APK at streetbite_capstone/build/app/outputs/flutter-apk/app-release.apk.
يحتاج
‏JDK 17 وMaven وخادم Appium يعمل على 127.0.0.1:4723، ومحاكي أو هاتف، وملف APK الصادر في streetbite_capstone/build/app/outputs/flutter-apk/app-release.apk.
Try it
See section 20, then run mvn test -Dtest=LoginTest and open target/screenshots — every step of the failing test is captured there.
جرّب
انظر القسم ٢٠ ثم نفّذ mvn test -Dtest=LoginTest وافتح target/screenshots؛ كل خطوة في الاختبار الفاشل مصوّرة هناك.
manual_qa/folder

The human test evidence: a 51-case test plan, its execution results and a closure report.

دليل الاختبار البشري: خطة بـ ٥١ حالة ونتائج تنفيذها وتقرير إغلاق.

Has
TestPlan_and_TestCases.xlsx (4 sheets: Test Plan, Test Cases, Traceability, Defect Log), TestClosureSummary.pdf, six PNG screenshots, four Python scripts that build those artefacts, and a README.
يحتوي
TestPlan_and_TestCases.xlsx (٤ أوراق: Test Plan وTest Cases وTraceability وDefect Log) وTestClosureSummary.pdf وست لقطات PNG وأربعة سكربتات Python تبني تلك المخرجات وREADME.
Does
Covers what automation cannot: visual fidelity to Figma, Arabic RTL, and behaviour on real hardware. It is also where the four device-only bugs were found.
يفعل
يغطي ما لا تقدر عليه الأتمتة: المطابقة البصرية لتصميم Figma، والاتجاه من اليمين لليسار بالعربية، والسلوك على عتاد حقيقي. وفيه وُجدت الأخطاء الأربعة التي تظهر على الجهاز فقط.
Needs
Python with openpyxl and reportlab to regenerate the workbook and the PDF.
يحتاج
Python مع openpyxl وreportlab لإعادة توليد المصنّف وملف PDF.
Try it
Run python manual_qa/scripts/build_qa_workbook.py, then apply_execution_results.py and apply_defect_log.py. Section 21 explains why the scripts, not hand-editing, are the source of truth.
جرّب
نفّذ python manual_qa/scripts/build_qa_workbook.py ثم apply_execution_results.py ثم apply_defect_log.py. يشرح القسم ٢١ لماذا تلك السكربتات هي مصدر الحقيقة لا التحرير اليدوي.

يمنح المناقش طبقة المفاهيم (المعمارية، الحالة، الأخطاء، الحماية، التنقل) وشرائح العرض. وكلاهما مكتفٍ بذاته: لا خادم ويب ولا خطوة بناء، ويعمل من ذاكرة USB.

عقد التصميم: ستة عشر تصديرًا للشاشات مع ملاحظات Dart التي ولّدها إضافة Figma.

_audit/tool

The (local-only) factory that generates the documentation from the source tree.

المصنع (المحلي فقط) الذي يولّد التوثيق من شجرة المصدر.

Has
build_site.py, gen15.py, gen16.py, imports.py, dump_docs.py, build_guide.py and this guide's content modules in guide/; plus decls.txt, fileindex.txt, dart_facts.txt, graph.mjs, find.mjs, dupes.mjs, qa_scan.py and docparts/ (20 HTML fragments).
يحتوي
build_site.py وgen15.py وgen16.py وimports.py وdump_docs.py وbuild_guide.py، ووحدات محتوى هذا الدليل في guide/؛ ومعها decls.txt وfileindex.txt وdart_facts.txt وgraph.mjs وfind.mjs وdupes.mjs وqa_scan.py وdocparts/ (عشرون قطعة HTML).
Does
Extracts facts instead of recalling them: declarations, line counts, import graphs, dead code, duplicated literals, and every file's doc-comment. The docs are then rendered from that inventory.
يفعل
تستخرج الحقائق بدل استذكارها: التصريحات وأعداد الأسطر ورسوم الاستيراد والشيفرة الميتة والتكرارات وتعليقات كل ملف. ثم يُعرض التوثيق من ذلك الجرد.
Needs
Python 3 and Node. Git-ignored on purpose — it is authoring tooling, and its scratch dumps are device evidence rather than source.
يحتاج
Python 3 وNode. مُستثناة من Git عن قصد: إنها أدوات تأليف، وتفرغاتها أدلة جهاز لا مصادر.
Try it
Run python _audit/imports.py then python _audit/build_guide.py. The second command fails loudly if any card in this guide points at a file that no longer exists.
جرّب
نفّذ python _audit/imports.py ثم python _audit/build_guide.py. الأمر الثاني يفشل بصوت عالٍ إذا أشارت أي بطاقة هنا إلى ملف لم يعد موجودًا.

How this document was made. Written against commit 07b200f. Every card was produced by reading the file it describes; the line counts, declaration names and import lists are extracted from the source tree by _audit/imports.py, and _audit/build_guide.py refuses to build if a card points at a Dart file that no longer exists. Nothing here is remembered from a previous draft.

Companion documents. docs/code-doc/index.html explains the concepts (architecture, state, errors, security) layer by layer; this guide answers the other question — what is each file for. docs/StreetBite_Capstone_Report_EN-AR.pptx is the slide deck for the defence itself.

Language. Both columns are on by default; the sidebar switches to English or Arabic only. Paths, identifiers and code are never translated, because Either<Failure, List<MealEntity>> reads the same in either language.

كيف صُنعت هذه الوثيقة. كُتبت عند الالتزام 07b200f. وكل بطاقة نُقلت بعد قراءة الملف الموصوف؛ وأعداد الأسطر وأسماء التصريحات وقوائم الاستيراد تُستخرج من شجرة المصدر بواسطة _audit/imports.py، و_audit/build_guide.py يرفض البناء إذا أشارت بطاقة إلى ملف Dart لم يعد موجودًا. ولا شيء هنا من الاستذكار.

الوثائق المكمّلة. يشرح docs/code-doc/index.html المفاهيم (المعمارية، الحالة، الأخطاء، الحماية) طبقة طبقة؛ أما هذا الدليل فيجيب عن السؤال الآخر: ما وظيفة كل ملف. وملف docs/StreetBite_Capstone_Report_EN-AR.pptx هو العرض التقديمي للمناقشة.

اللغة. العمودان ظاهران افتراضيًا، ويحوّلهما الشريط الجانبي إلى الإنجليزية أو العربية وحدها. ولا تُترجَم المسارات والمعرّفات والشفرة أبدًا، لأن Either<Failure, List<MealEntity>> تُقرأ بالشكل نفسه في اللغتين.
