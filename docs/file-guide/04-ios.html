04 ios/ — present, configured, deliberately unused‏ios/ — موجود ومُهيّأ وغير مستخدَم عن قصد

The capstone ships as an Android APK, but the iOS project stays in the tree because flutter create made it and because it proves the code is genuinely cross-platform: nothing in lib/ uses an Android-only API. It is also the folder that documents one honest limitation — flutter_launcher_icons 0.14.4 rewrites project.pbxproj with an invalid ASSETCATALOG_COMPILER_GENERATE_SWIFT_ASSET_SYMBOL_EXTENSIONS value, so ios: stays false in pubspec.yaml.

يُسلَّم مشروع التخرّج كملف APK لنظام Android، لكن مشروع iOS يبقى في الشجرة لأن flutter create أنشأه، ولأنه يُثبت أن الشيفرة متعددة المنصات فعلًا: لا شيء في lib/ "يستعمل واجهة Android حصرًا. وهو أيضًا المجلد الذي يوثّق قيدًا بصدق: الإضافة " "flutter_launcher_icons إصدار 0.14.4 تعيد كتابة project.pbxproj بقيمة غير صالحة " "لـ ASSETCATALOG_COMPILER_GENERATE_SWIFT_ASSET_SYMBOL_EXTENSIONS، ولهذا بقي " "ios: على false في pubspec.yaml.

streetbite_capstone/ios/Runner/AppDelegate.swiftnative

The iOS application delegate — seven lines of template code.

مندوب تطبيق iOS — سبعة أسطر من شيفرة القالب.

Has
@UIApplicationMain class conforming to FlutterAppDelegate and overriding application(_:didFinishLaunchingWithOptions:).
يحتوي
صنف @UIApplicationMain يوافق FlutterAppDelegate ويعيد تعريف application(_:didFinishLaunchingWithOptions:).
Does
The native entry point iOS calls before Flutter draws. Unmodified, which is itself the evidence that no iOS-specific bridging was needed.
يفعل
نقطة الدخول الأصلية التي تستدعيها iOS قبل أن ترسم Flutter. وهو بلا تعديل، وهذا بنفسه دليل على أن لا حاجة إلى جسر خاص بـ iOS.
Needs
The Flutter engine framework.
يحتاج
إطار محرك Flutter.
Try it
If you ever do need native iOS code (a plugin callback, a background mode), this is the file — and the comment you must add explaining why.
جرّب
إن احتجت شيفرة iOS أصلية يومًا (استدعاء إضافة أو وضع خلفية) فهذا هو ملفه — والتعليق الذي يجب أن يشرح السبب.
streetbite_capstone/ios/Runner/Info.plistcfg

The iOS bundle manifest: identifiers, orientations, storyboard names.

بيان حزمة iOS: المعرّفات والاتجاهات وأسماء لوحات القصة.

Has
CFBundleDisplayName/Identifier/ShortVersionString/Version bound to $(PRODUCT_NAME) and $(FLUTTER_BUILD_NAME), UISupportedInterfaceOrientations (portrait + upsidedown), UILaunchStoryboardName, UIMainStoryboardFile, the scene manifest and CADisableMinimumFrameDurationOnPhone.
يحتوي
CFBundleDisplayName/Identifier/ShortVersionString/Version مرتبطة بـ $(PRODUCT_NAME) و$(FLUTTER_BUILD_NAME)، وUISupportedInterfaceOrientations (عمودي ومعكوس) وUILaunchStoryboardName وUIMainStoryboardFile وبيان المشهد وCADisableMinimumFrameDurationOnPhone.
Does
Declares the app to iOS. Note there is no NSFaceIDUsageDescription: Face ID is an Android-side feature in this release, and the key would be required before enabling local_auth here.
يفعل
يعلن التطبيق لـ iOS. ولاحظ أنه لا يوجد NSFaceIDUsageDescription: Face ID في هذا الإصدار ميزة على جهة Android، وهذا المفتاح مطلوب قبل تفعيل local_auth هنا.
Needs
Xcode's build settings, which supply the $(...) variables.
يحتاج
إعدادات بناء Xcode التي تمدّ المتغيرات $(...).
Try it
Add NSFaceIDUsageDescription, build for a simulator and turn on the biometric sign-in path. That is the iOS to-do list written as one key.
جرّب
أضف NSFaceIDUsageDescription وابنِ لمحاكي وفعّل مسار الدخول بالبصمة. تلك هي قائمة مهام iOS مكتوبة كمفتاح واحد.
streetbite_capstone/ios/Runner.xcodeproj/project.pbxprojcfg

Xcode's project file: targets, build phases and configuration.

ملف مشروع Xcode: الأهداف ومراحل البناء والإعدادات.

Has
630 lines describing the Runner target, the Frameworks and Resources build phases, debug/release/profile configurations and the Flutter shell-script build phase.
يحتوي
٦٣٠ سطرًا تصف هدف Runner ومراحل Frameworks وResources وإعدادات debug/release/profile ومرحلة بناء نص Flutter.
Does
Makes the project openable in Xcode at all. Mostly generated noise — which is why flutter_launcher_icons touching it was rejected.
يفعل
يجعل المشروع قابلًا للفتح في Xcode أصلًا. وأغلبه ضجيج مولَّد — وهذا رفضُنا لأداة تلمسه مثل flutter_launcher_icons.
Needs
Xcode 15+ and the CocoaPods/SPM integration in ios/Flutter/.
يحتاج
‏Xcode 15 فأحدث وتكامل CocoaPods/SPM في ios/Flutter/.
Try it
Diff it after a plugin run and you will see why a tool that rewrites this file with an invalid YES/NO value breaks every build.
جرّب
قارنه بعد تشغيل إضافة لترى لماذا تكسر كلَّ بناء أداةٌ تعيد كتابة هذا الملف بقيمة YES/NO غير صالحة.
streetbite_capstone/ios/Flutter/ · Runner/Assets.xcassets · Base.lprojres

The remaining iOS furniture: xcconfig files, template icons and storyboards.

بقية أثاث iOS: ملفات xcconfig وأيقونات القالب ولوحات القصة.

Has
Debug.xcconfig, Release.xcconfig, Generated.xcconfig, AppFrameworkInfo.plist, the AppIcon and LaunchImage sets, and Main.storyboard / LaunchScreen.storyboard.
يحتوي
Debug.xcconfig وRelease.xcconfig وGenerated.xcconfig وAppFrameworkInfo.plist، ومجموعتا AppIcon وLaunchImage، وMain.storyboard وLaunchScreen.storyboard.

Connects the Xcode build to the engine Flutter ships, and keeps the template icon set that pubspec.yaml deliberately refuses to overwrite.
يفعل
تربط بناء Xcode بالمحرك الذي توفره Flutter، وتُبقي طقم أيقونات القالب الذي يرفض pubspec.yaml الكتابة عليه عمدًا.

The Flutter tool writes Generated.xcconfig and ephemeral/ on every build.

أداة Flutter تكتب Generated.xcconfig وephemeral/ عند كل بناء.
Try it

جرّب
اقرأ Generated.xcconfig: فيه مسار المحرك وقيم FLUTTER_BUILD_* — مقابل local.properties في iOS.

How this document was made. Written against commit 07b200f. Every card was produced by reading the file it describes; the line counts, declaration names and import lists are extracted from the source tree by _audit/imports.py, and _audit/build_guide.py refuses to build if a card points at a Dart file that no longer exists. Nothing here is remembered from a previous draft.

Companion documents. docs/code-doc/index.html explains the concepts (architecture, state, errors, security) layer by layer; this guide answers the other question — what is each file for. docs/StreetBite_Capstone_Report_EN-AR.pptx is the slide deck for the defence itself.

Language. Both columns are on by default; the sidebar switches to English or Arabic only. Paths, identifiers and code are never translated, because Either<Failure, List<MealEntity>> reads the same in either language.

كيف صُنعت هذه الوثيقة. كُتبت عند الالتزام 07b200f. وكل بطاقة نُقلت بعد قراءة الملف الموصوف؛ وأعداد الأسطر وأسماء التصريحات وقوائم الاستيراد تُستخرج من شجرة المصدر بواسطة _audit/imports.py، و_audit/build_guide.py يرفض البناء إذا أشارت بطاقة إلى ملف Dart لم يعد موجودًا. ولا شيء هنا من الاستذكار.

الوثائق المكمّلة. يشرح docs/code-doc/index.html المفاهيم (المعمارية، الحالة، الأخطاء، الحماية) طبقة طبقة؛ أما هذا الدليل فيجيب عن السؤال الآخر: ما وظيفة كل ملف. وملف docs/StreetBite_Capstone_Report_EN-AR.pptx هو العرض التقديمي للمناقشة.

اللغة. العمودان ظاهران افتراضيًا، ويحوّلهما الشريط الجانبي إلى الإنجليزية أو العربية وحدها. ولا تُترجَم المسارات والمعرّفات والشفرة أبدًا، لأن Either<Failure, List<MealEntity>> تُقرأ بالشكل نفسه في اللغتين.
